This page compares `nanime` with the Vue packages that wrap AnimeJS v4,
based on each package's source and README as of September 2026. The
`nanime` maintainers wrote it, so
[open an issue](https://github.com/astraldev/nanime/issues) if something is
wrong. For Nuxt modules, see
[Compared with Nuxt modules](/getting-started/vs-nuxt-modules).

## Where does nanime stand out?

- **Made for Nuxt.** Composables and components are auto-imported, and
  AnimeJS modules are pre-bundled by Vite. No plugin file, no imports.
- **Plain getters.** Parameters can be a getter, a `ref` or a plain object.
- **The real instance.** Composables return the AnimeJS instance itself.
- **Transition components.**[`<AnimeTransition>`](/components/transitions) and
  [`<AnimeTransitionGroup>`](/components/transitions#lists) animate `v-if`
  and `v-for` changes, list moves included, with no CSS.

## How do lists animate in and out?

[`<AnimeTransitionGroup>`](/components/transitions#lists) scales items in
and out of a `v-for` list, and AnimeJS
[layout](/composables/use-anime-layout) slides the rest to their new
places:

::render-code-block-preview

::

::code-group
```vue [nanime]
<template>
  <AnimeTransitionGroup
    tag="ul"
    enter-animation="scale"
    leave-animation="scale"
    class="relative"
  >
    <li v-for="item in items" :key="item">{{ item }}</li>
  </AnimeTransitionGroup>
</template>
```

```vue [vue-animejs]
<script setup lang="ts">
import { useRawAnimate } from '@juleshry/vue-animejs'

function onEnter(el: Element, done: () => void) {
  useRawAnimate(el, { opacity: [0, 1], scale: [0.85, 1], onComplete: done })
}

function onLeave(el: Element, done: () => void) {
  useRawAnimate(el, { opacity: 0, scale: 0.85, onComplete: done })
}
</script>

<template>
  <TransitionGroup tag="ul" :css="false" @enter="onEnter" @leave="onLeave">
    <li v-for="item in items" :key="item">{{ item }}</li>
  </TransitionGroup>
</template>
```
::

Neither `vue-animejs` nor `v-anime` has transition components, so both use
Vue's `<TransitionGroup>` with `:css="false"` and animate in its hooks. The
other items jump to their new places unless you add move code yourself.

## How does nanime differ from vue-animejs?

[`vue-animejs`](https://github.com/juleshry/vue-animejs) covers almost the
same AnimeJS v4 APIs, and adds five directives such as `v-animate`, plus
`useTimer` and `useScope`. It is a Vue package, so in Nuxt each component
imports what it uses, or the app registers it in `imports.presets`.

Its composables take reactive options as a `ref` or `computed` and return
wrapper functions like `play` and `pause`, with the instance in an
`animation` ref. `nanime` also takes a getter, returns the AnimeJS instance
itself, and with [`keepTime`](/getting-started/configuration) continues a
rebuilt animation from the old playhead.

## How does nanime differ from v-anime?

[`v-anime`](https://github.com/Upperstrange/v-anime) wraps the AnimeJS v4
`createScope` function. Its `useAnime` runs your code once in `onMounted`
and reverts the scope on unmount, so changing a `ref` afterwards does not
rebuild anything. It ships TypeScript source without a build step and does
not list `animejs` as a dependency.

## Which should you pick?

- `nanime` for a Nuxt app, transition components, or rebuilds that keep
  the playhead.
- `vue-animejs` for directives, `useTimer` or `useScope`, or a Vue app
  without Nuxt.
- `v-anime` for a thin wrapper around an AnimeJS scope.
