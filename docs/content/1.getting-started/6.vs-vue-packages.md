This page compares `nanime` with the Vue packages that wrap AnimeJS v4.
The `nanime` maintainers wrote it, and the facts come from each package's
source and README as of September 2026. If something is wrong or out of
date,
[open an issue](https://github.com/astraldev/nanime/issues).
For Nuxt modules and AnimeJS on its own, see
[vs Nuxt modules](/getting-started/vs-nuxt-modules).

## Where does nanime stand out?

- **Made for Nuxt.** It installs as a module. Composables and components
  are auto-imported, AnimeJS modules are pre-bundled by Vite, and defaults
  live in `nuxt.config.ts`. No plugin file, no import lines.
- **Plain getters.** Parameters can be a getter, a `ref` or a plain
  object. No `computed` wrapper needed.
- **The real instance.** Composables return the AnimeJS instance, so every
  method and property from the AnimeJS docs is there.
- **Transition components.**
  [`<AnimeTransition>`](/components/transitions) and
  [`<AnimeTransitionGroup>`](/components/transitions#lists) animate
  `v-if` and `v-for` changes with AnimeJS, including list moves, with no
  CSS to write.

## How do lists animate in and out?

[`<AnimeTransitionGroup>`](/components/transitions#lists) animates items
that enter and leave a `v-for` list. AnimeJS
[layout](/composables/use-anime-layout) slides the other items to their
new places. Each tab scales items in and out, like the preview:

::

::code-group
```vue [nanime]
<script setup lang="ts">
const items = ref([1, 2, 3, 4, 5])
</script>

<template>
  <AnimeTransitionGroup
    tag="ul"
    enter-animation="scale"
    leave-animation="scale"
    class="relative"
  >
    <li v-for="item in items" :key="item">{{ item }}</li>
  </AnimeTransitionGroup>
</template>
```

```vue [vue-animejs]
<script setup lang="ts">
import { useRawAnimate } from '@juleshry/vue-animejs'

const items = ref([1, 2, 3, 4, 5])

function onEnter(el: Element, done: () => void) {
  useRawAnimate(el, {
    opacity: [0, 1],
    scale: [0.85, 1],
    duration: 300,
    ease: 'out(3)',
    onComplete: done,
  })
}

function onLeave(el: Element, done: () => void) {
  useRawAnimate(el, {
    opacity: 0,
    scale: 0.85,
    duration: 200,
    ease: 'in(3)',
    onComplete: done,
  })
}
</script>

<template>
  <TransitionGroup tag="ul" :css="false" @enter="onEnter" @leave="onLeave">
    <li v-for="item in items" :key="item">{{ item }}</li>
  </TransitionGroup>
</template>
```

```vue [v-anime]
<script setup lang="ts">
import { animate } from 'animejs'
import { useAnimeController } from 'v-anime'

const root = ref(null)
const scope = ref(null)
const items = ref([1, 2, 3, 4, 5])

function enter(el: Element, done: () => void) {
  animate(el, {
    opacity: [0, 1],
    scale: [0.85, 1],
    duration: 300,
    ease: 'out(3)',
    onComplete: done,
  })
}

function leave(el: Element, done: () => void) {
  animate(el, {
    opacity: 0,
    scale: 0.85,
    duration: 200,
    ease: 'in(3)',
    onComplete: done,
  })
}

const trigger = useAnimeController({
  root,
  scope,
  animations: [
    { methodName: 'enter', animationFunction: enter },
    { methodName: 'leave', animationFunction: leave },
  ],
})
</script>

<template>
  <div ref="root">
    <TransitionGroup
      tag="ul"
      :css="false"
      @enter="(el, done) => trigger('enter', el, done)"
      @leave="(el, done) => trigger('leave', el, done)"
    >
      <li v-for="item in items" :key="item">{{ item }}</li>
    </TransitionGroup>
  </div>
</template>
```
::

`vue-animejs` and `v-anime` have no transition components. Both tabs use
Vue's `<TransitionGroup>` with `:css="false"`. Its `@enter` and `@leave`
hooks start an animation and call `done` when it completes. Vue animates
moves only through a CSS move class, so the other items jump to their new
places. Smooth moves take extra code, for example a `useLayout` call in
`vue-animejs`.

## How does nanime differ from vue-animejs?

[`vue-animejs`](https://github.com/juleshry/vue-animejs)
covers almost the same AnimeJS v4 APIs as `nanime`. It also ships five
directives, such as `v-animate` and `v-draggable`, for animating from the
template alone. It has `useTimer` and `useScope` composables, which
`nanime` does not.

It is a Vue package rather than a Nuxt module. In Nuxt, each component
imports the composables it uses, or the app registers them through
`imports.presets` in `nuxt.config.ts`.

The two packages handle updates differently. `nanime` accepts a getter as
parameters, and refreshes a draggable in place when one of its options
changes, rather than rebuilding it. With
[`keepTime`](/getting-started/configuration), a rebuilt animation
continues from where the old one was. `vue-animejs` returns wrapper
functions like `play` and `pause`, with the instance in an `animation`
ref. `nanime` returns the AnimeJS instance itself.

Each tab makes a box draggable, with snapping that a toggle turns on and
off, like the preview:

```vue [nanime]
<script setup lang="ts">
const box = useTemplateRef('box')

  y: false,
  snap: () => (snapping.value ? 50 : 0),
})

```

```vue [vue-animejs]
<script setup lang="ts">
import { useDraggable } from '@juleshry/vue-animejs'

const box = useTemplateRef('box')
const snapping = ref(true)

useDraggable(box, computed(() => ({
  y: false,
  snap: snapping.value ? 50 : 0,
})))
</script>
```

```vue [v-anime]
<script setup lang="ts">
import { createDraggable, type Draggable } from 'animejs'
import { useAnime } from 'v-anime'

const root = ref(null)
const scope = ref(null)
const snapping = ref(true)
let draggable: Draggable | undefined

useAnime({
  root,
  scope,
  animeFunctions: [() => {
    draggable = createDraggable('.box', {
      y: false,
      snap: () => (snapping.value ? 50 : 0),
    })
  }],
})

watch(snapping, () => draggable?.refresh())
</script>
```
::

## How does nanime differ from v-anime?

[`v-anime`](https://github.com/Upperstrange/v-anime)
builds on the AnimeJS v4 `createScope` function. Its `useAnime` composable
runs your animation code once in `onMounted` and reverts the scope on
unmount. Changing a `ref` afterwards does not rebuild anything.
`useAnimeController` registers named scope methods that the component
calls later.

The package ships TypeScript source with no build step. It does not list
`animejs` as a dependency, so the project installs AnimeJS itself and needs
a bundler that compiles TypeScript from `node_modules`.

## Which should you pick?

- Pick `nanime` for a Nuxt app, or for transition components and rebuilds
  that keep the playhead.
- Pick `vue-animejs` for directives, `useTimer` or `useScope`, or for a
  Vue app without Nuxt.
- Pick `v-anime` for a thin wrapper that creates an AnimeJS scope on
  mount and reverts it on unmount.
