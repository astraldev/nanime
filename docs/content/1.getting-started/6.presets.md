A preset bundles transition styles, component defaults and composable
defaults into one object. It sets entrances, exits, list moves, layout
changes and composable parameters together, so the motion of an app
comes from one place.

## Pick a built-in preset

::warning
The three built-in presets are still being tuned: today each one adds no
defaults of its own. Define a preset inline to use the layer now.
::

| Preset | Intended motion |
| :--- | :--- |
| `nanime/presets/formal` | Calm and precise, with no overshoot. Fast, even timing. |
| `nanime/presets/elegant` | Smooth and slow, with soft easing and no bounce. |
| `nanime/presets/playful` | Bouncy, with overshoot and a slower settle. |

Set it in `app.config.ts`. The config takes the imported object rather
than a preset name:

```ts [app/app.config.ts]
import formal from 'nanime/presets/formal'

export default defineAppConfig({
  nanime: {
    preset: formal,
  },
})
```

A preset can hold easing functions, which `nuxt.config.ts` cannot put into
runtime config. In a plain Vue app, pass the preset to `configureNanime()`.
See [Vue without Nuxt](/getting-started/vue).

## How a preset resolves

A preset is the lowest layer. These rules decide what it contributes:

- **Component props** resolve per prop: the prop, the nearest
  `provideAnimeDefaults()`, `app.config.ts`, the preset, then the built-in.
- **Composable entries** are chosen whole: a
  `provideAnimeDefaults({ composables })` entry, then
  `nanime.composables` in `app.config.ts`, then the preset. A composable
  call then merges its parameters over the chosen entry by top-level key,
  so a passed key wins where both set it.
- **Style names** resolve in `nanime.transitions` first, then in the
  preset's `shared`, then in the built-in styles. Enter and leave resolve
  independently, so one can come from the preset and the other from a
  built-in.

[Configuration](/getting-started/configuration#how-a-default-is-picked)
lists the full order.

## Write a preset

### Start from three keys

A preset has three keys:

| Key | Holds | Required |
| :--- | :--- | :--- |
| `shared` | Named transition styles the preset adds, in the same shape as `nanime.transitions`. | No |
| `components` | Default props for `transition`, `transitionGroup` and `layoutGroup`. | Yes |
| `composables` | Default parameters for `animate` and `draggable`. | Yes |

`components` and `composables` must be present, and so must all three
entries inside `components`. Empty objects are fine.

### Assemble a complete preset

A preset is a plain object, so the app-wide one goes straight into
`app.config.ts`:

```ts [app/app.config.ts]
export default defineAppConfig({
  nanime: {
    preset: {
      shared: {
        pop: {
          enter: { opacity: [0, 1], scale: [0.4, 1], duration: 240, ease: 'outBack(3)' },
          leave: { opacity: 0, scale: 0.4, duration: 140, ease: 'in(3)' },
          move: { duration: 200, ease: 'out(3)' },
        },
      },
      components: {
        transition: { animation: 'pop' },
        transitionGroup: { animation: 'pop' },
        layoutGroup: { layoutOptions: { duration: 400, ease: 'out(3)' } },
      },
      composables: {
        animate: { duration: 400, ease: 'out(3)' },
        draggable: { releaseEase: 'out(3)' },
      },
    },
  },
})
```

### Use the styles it adds

`shared` holds named transition styles, in the same shape as a style in
[transition styles](/components/transition-styles). The `pop` style is one
of them. The animation props on
[the components](/components/transitions) take these names, the same as a
style from `app.config.ts`:

```vue
<AnimeTransition enter-animation="fade" leave-animation="pop">
  <div v-if="show" />
</AnimeTransition>
```

A name in both `app.config.ts` and the preset uses the `app.config.ts`
style, and a preset style with a built-in name replaces the built-in inside
its scope.

### Set its composable defaults

`composables.animate` sets the default parameters for
[`useAnimate`](/composables/use-animate), and `composables.draggable` sets
the default options for [`useDraggable`](/composables/use-draggable). Both
are typed like `nanime.composables`. A composable call merges its
parameters or options over the preset's entry by top-level key, so a
passed key wins where both set it.
[Configuration](/getting-started/configuration/composable-defaults)
covers the entries.

## Scope a preset to part of the app

`provideAnimeDefaults({ preset })` replaces the preset for everything
rendered below the component that calls it. The app-wide preset is not
used inside, and a preset from an outer scope is replaced whole.

The demo provides one of two presets to its own subtree. Both define a
style called `sway`, and both ask `transition` and `transitionGroup` for
`animation: 'sway'`. Only the values behind the name differ: `Snappy`
scales the box in over 220ms and moves list items over 150ms, while
`Glide` slides it in over 700ms and moves items over 800ms. The template
never mentions a preset, so the only change is the preset the provider
supplies.

A preset choice replays the box and the list, and the `Add`, `Remove` and
`Shuffle` buttons use the active preset.

</script>
