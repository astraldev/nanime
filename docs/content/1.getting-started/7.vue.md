`nanime` ships a second entry point, `nanime/vue`, for Vue 3 apps built
without Nuxt. It re-exports the composables, the three components, and the
types, easings, utilities and proxies the module provides.
`configureNanime()` sets the app-wide config that the module otherwise
reads from `app.config.ts` and `nuxt.config.ts`.

## Install the package

`nanime/vue` is part of the `nanime` package, so install the `nanime`
package as usual:

::code-group
```bash [pnpm]
pnpm add nanime
```

```bash [npm]
npm install nanime
```

```bash [bun]
bun add nanime
```
::

Without Nuxt there are no auto-imports and no `#nanime/*` aliases. Import
everything from `nanime/vue` and register each component by hand.

## Pre-bundle the AnimeJS submodules

The Nuxt module pre-bundles the `animejs/*` submodules it imports. In a
plain Vite app, list the ones you use under `optimizeDeps.include` so Vite
does not reload the page when they first load:

```ts [vite.config.ts]
import { defineConfig } from 'vite'

export default defineConfig({
  optimizeDeps: {
    include: [
      'animejs/animation',
      'animejs/layout',
      'animejs/timeline',
      'animejs/text',
      'animejs/utils',
    ],
  },
})
```

## Configure the app

Call `configureNanime()` on the app before it mounts. The config has the
same shape as the `nanime` key in `app.config.ts`: `keepTime`,
`reducedMotion`, `preset`, `transitions`, `components` and `composables`.

```ts [main.ts]
import { createApp } from 'vue'
import { configureNanime } from 'nanime/vue'
import App from './App.vue'

const app = createApp(App)

configureNanime(app, {
  reducedMotion: 'system',
  components: {
    transition: { enterAnimation: 'slide-up', mode: 'out-in' },
  },
  composables: {
    animate: { duration: 600, ease: 'out(3)' },
  },
})

app.mount('#app')
```

The config is stored on the Vue app. Two apps on one page keep separate
config. Pass a `ref` or getter as the second argument when the config
changes at runtime, such as a reduced motion toggle.

[Configuration](/getting-started/configuration) covers each field, and
[Presets](/getting-started/presets) covers `preset`.

## Register the components

Register all three in the same `main.ts`:

```ts [main.ts]
import { AnimeLayoutGroup, AnimeTransition, AnimeTransitionGroup } from 'nanime/vue'

app.component('AnimeTransition', AnimeTransition)
app.component('AnimeTransitionGroup', AnimeTransitionGroup)
app.component('AnimeLayoutGroup', AnimeLayoutGroup)
```

Or import one in the component that uses it:

```vue [App.vue]
<script setup lang="ts">
import { AnimeTransition } from 'nanime/vue'
</script>

<template>
  <AnimeTransition>
    <div v-if="show" />
  </AnimeTransition>
</template>
```

The `nanime/vue` entry imports the components' stylesheet, so there is no
stylesheet to import.

## Import the rest of the API

Every other export also comes from `nanime/vue`:

- The easings, utilities and proxies that Nuxt exposes as `#nanime/*`
  aliases.
- The public types.
- The `animate` and `createTimer` functions.

```ts [main.ts]
import { animate, morphTo, stagger } from 'nanime/vue'
import type { NanimeConfig } from 'nanime/vue'
```

## Scope defaults to part of the app

`provideAnimeDefaults()` works in any component and sets defaults for
everything rendered below it:

```vue [SettingsPanel.vue]
<script setup lang="ts">
import { provideAnimeDefaults } from 'nanime/vue'

provideAnimeDefaults({
  composables: { animate: { duration: 300 } },
  transition: { enterAnimation: 'scale' },
})
</script>
```

A `composables` entry in `provideAnimeDefaults()` replaces the one from
`configureNanime()` whole, not key by key. A composable call merges its
parameters or options over the chosen entry by top-level key, so a passed
key wins where both set it.

`nanime` uses a preset only when neither the app config nor a provider
sets defaults for that composable.
[Configuration](/getting-started/configuration#how-a-default-is-picked)
lists the full order for composables and components.

`provideAnimeDefaults()` cannot change `transitions` or `reducedMotion`.
Both stay in the app config.

## Render on the server

Composables wait for their component to mount before they touch the DOM,
so a call in `setup()` during server rendering waits for hydration. The
components start their animations on mount too. Create the app for each
request and call `configureNanime()` there, so the config belongs to that
request.
