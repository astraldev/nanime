Most animation performance advice is about the browser, not about any
library: which properties are cheap to animate, what forces a reflow, and
what the compositor runs on its own. These guides cover those topics:

- [Animations and performance](https://web.dev/articles/animations-and-performance){target="_blank"}
- [Avoid large, complex layouts and layout thrashing](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing){target="_blank"}
- [Stick to compositor-only properties](https://web.dev/articles/stick-to-compositor-only-properties-and-manage-layer-count){target="_blank"}
- [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion){target="_blank"}

In short, animate `translateX`, `translateY`, `scale`, `rotate` and
`opacity`. Animating `width` or `top` makes the browser recompute layout
on every frame. The rest of this page is about `nanime` itself.

## Choosing between the two engines

[`useWaapiAnimate`](/composables/use-waapi-animate) runs the animation
through the browser's Web Animations API. For `transform` and `opacity`,
the browser runs the animation on the compositor thread. The animation
keeps its frame rate while the main thread is busy, for example during
hydration. Modals, dropdowns, page entrances and ambient loops all fit.

```vue
<script setup lang="ts">
const modal = useTemplateRef('modal')

useWaapiAnimate(modal, {
  transform: ['translateY(20px) scale(0.95)', 'translateY(0px) scale(1)'],
  opacity: [0, 1],
  duration: 300,
  ease: 'cubic-bezier(0.2, 0, 0, 1)',
})
</script>
```

[`useAnimate`](/composables/use-animate) runs on the main thread through
`requestAnimationFrame`, so it competes with everything else happening
there. Reach for it when you need something WAAPI has no way to express:

- SVG morphing with `morphTo`
- Motion paths with `createMotionPath`
- SVG line drawing with `createDrawable`
- Text scrambling through [`useScrambleText`](/composables/use-scramble-text)
- Plain JavaScript objects and numbers

Both engines can run in one component. In the
[Road trip example](/examples/road-trip), the booking spinner turns with
`useWaapiAnimate` while `useScrambleText` updates the status line next to
it on the main thread.

## Driving fast updates with useAnimatable

Cursor tracking, scroll handlers and drag events fire many times a second.
Creating a new animation on each event builds dozens of instances a
second, and each one replaces the last before it finishes.

[`useAnimatable`](/composables/use-animatable) creates one instance up
front and exposes each property as a setter. Calling a setter such as
`animatable.translateX(120)` tweens the property from its current value to
`120`.

```vue
<script setup lang="ts">
const circle = useTemplateRef('circle')

const animatable = useAnimatable(circle, {
  translateX: 0,
  translateY: 0,
  ease: 'outExpo',
  duration: 300,
})

function onMouseMove(event: MouseEvent) {
  animatable.translateX(event.clientX)
  animatable.translateY(event.clientY)
}
</script>
```

`useAnimate` with a getter such as `() => ({ x: mouseX.value })` also
follows the cursor, but each mouse move reverts the running animation and
builds a new one. Getters are for values that change
occasionally, like a prop or a media query. A plain object is enough when
nothing changes at all.

## Keeping the returned instance intact

Call methods on the object a composable returns, as in
`animation.play()`. Destructuring that object breaks it in two ways:

- `play()` throws, because it no longer has an instance to run on.
- `progress` is a number frozen at the moment of destructuring.

```ts
// play() throws when called
const { play, pause, progress } = useAnimate(box, { ... })

// keeps it
const animation = useAnimate(box, { ... })
animation.play()
```

## Passing an element rather than a selector

A target can be a selector string, an element, a component instance or a
template ref. In a component that renders more than once on a page,
`'.card'` resolves against the whole document, so each copy of the
component animates the `.card` elements of every other copy too. A
template ref points at one element and needs no lookup.

```vue
<script setup lang="ts">
const card = useTemplateRef('card')

useAnimate(card, {
  scale: [0.9, 1],
  opacity: [0, 1],
  duration: 400,
})
</script>

<template>
  <div ref="card" class="card">Content</div>
</template>
```

## Keeping split text short

[`useSplitText`](/composables/use-split-text) wraps each line, word or
character in its own element. A heading split into characters is a few dozen spans. An article
split the same way is a few thousand for the browser to style and lay out.

Split headings, hero titles and short callouts. Prefer `{ words: true }` or
`{ lines: true }` over `{ chars: true }` when the effect still works per
word or per line. The composable returns `lines`, `words` and `chars`
refs, so switching to words means passing `{ words: true }` and animating
`words` instead of `chars`:

```vue
<script setup lang="ts">
import { stagger } from '#nanime/utils'

const heading = useTemplateRef('heading')

// one span per character, on a short heading
const { chars } = useSplitText(heading, { chars: true })

useAnimate(chars, {
  translateY: [20, 0],
  opacity: [0, 1],
  delay: stagger(40),
  duration: 400,
  ease: 'outQuad',
})
</script>

<template>
  <h2 ref="heading">Ship it</h2>
</template>
```
