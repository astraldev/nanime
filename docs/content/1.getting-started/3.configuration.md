`nanime` runs with no configuration. Three options exist if the defaults do
not fit.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nanime'],
  nanime: {
    // options go here
  }
})
```

### `composables`
- **Type**: `boolean`
- **Default**: `true`

Whether the module auto-imports its composables. Set it to `false` to
import them yourself:

```ts
nanime: {
  composables: false
}
```

```ts
import { useAnimate } from '#nanime/composables'
```

### `components`
- **Type**: `boolean`
- **Default**: `true`

Whether the module registers
[`<AnimeTransition>`](/components/transitions),
[`<AnimeTransitionGroup>`](/components/transitions#lists) and
[`<AnimeLayoutGroup>`](/components/layout-group) as global components,
along with the small stylesheet they use. Set it to `false` if you do not
use them:

```ts
nanime: {
  components: false
}
```

### `keepTime`
- **Type**: `boolean`
- **Default**: `false`

The default for every composable's own `keepTime` option. `true` carries an
animation's playhead across a rebuild, so it continues instead of
restarting when its reactive inputs change. A composable's own third
argument still wins over this:

```ts
nanime: {
  keepTime: true
}
```

```ts
// restarts on rebuild even though the module default is true
useAnimate(target, { x: 100 }, { keepTime: false })
```

## App config

Custom [transition styles](/components/transition-styles) go under the
`nanime.transitions` key in `app.config.ts`, not `nuxt.config.ts`. App
config is bundled with the app, so styles can hold functions, such as a
random `delay`.

```ts [app/app.config.ts]
export default defineAppConfig({
  nanime: {
    transitions: {
      pop: {
        enter: { opacity: [0, 1], scale: [0.4, 1], duration: 700 },
        leave: { opacity: 0, scale: 0.4, duration: 250 },
      },
    },
  },
})
```

Each style can set `enter`, `leave` and `move`. A style with a built-in
name, such as `fade`, replaces the built-in.

### Component defaults

Default props for each component go under `nanime.components`, keyed
`transition`, `transitionGroup` and `layoutGroup`. A prop passed to the
component wins over its default.

```ts [app/app.config.ts]
export default defineAppConfig({
  nanime: {
    components: {
      transition: { enterAnimation: 'slide-up', mode: 'out-in' },
      transitionGroup: { moveAnimation: { duration: 600, ease: 'out(4)' } },
      layoutGroup: { layoutOptions: { duration: 500 } },
    },
  },
})
```

### Defaults for part of the app

`provideAnimeDefaults()` sets component defaults for everything rendered
below the component that calls it. It takes the same shape as
`nanime.components`, or a getter that returns one.

```vue [components/SettingsPanel.vue]
<script setup lang="ts">
provideAnimeDefaults({
  transition: { enterAnimation: 'scale' },
})
</script>
```

Defaults merge per prop, from lowest to highest priority:

1. The built-in default.
2. `nanime.components` in `app.config.ts`.
3. Each `provideAnimeDefaults()` call, outermost first.
4. The prop passed to the component.

A default set to `undefined` leaves the one below it in place, so a getter
can switch a default on and off. A default holding AnimeJS params, such as
`enterAnimation`, replaces the one below it as a whole. The layout group's
`layoutOptions` is the exception: its keys merge, so `duration` from
`app.config.ts` and `ease` from a provider both apply.
