This page compares `nanime` with using AnimeJS on its own in Nuxt, and with
the other Nuxt modules for AnimeJS. The `nanime` maintainers wrote it, and
the facts come from each package's source and README as of September 2026.
If something is wrong or out of date,
[open an issue](https://github.com/astraldev/nanime/issues).
For Vue packages, see [Compared with Vue packages](/getting-started/vs-vue-packages).

## Where does nanime stand out?

- **Built for AnimeJS v4.** One composable per v4 API: animate, WAAPI,
  animatable, timeline, draggable, split text, scramble text, scroll and
  layout.
- **Nuxt-native.** Composables and components are auto-imported,
  AnimeJS modules are pre-bundled by Vite, and defaults like
  [`keepTime`](/getting-started/configuration) live in `nuxt.config.ts`.
- **Nothing hidden.** Each composable returns the AnimeJS instance itself,
  so the AnimeJS docs apply to it line for line.
- **Small.** The runtime depends on `animejs` and `defu`, nothing else.

## What does nanime add over AnimeJS on its own?

AnimeJS works in Nuxt without any wrapper. The cost is lifecycle code in
every component that animates. Each tab staggers a row of cards in on
mount, with a button that replays it, like the preview:

::code-group
```vue [nanime]
<script setup lang="ts">
import { stagger } from '#nanime/utils'

const cards = useTemplateRef('cards')

const entrance = useAnimate(cards, {
  translateY: [16, 0],
  opacity: [0, 1],
  delay: stagger(80),
})
</script>

<template>
  <button @click="entrance.restart()">Replay</button>
  <div v-for="n in 4" :key="n" ref="cards" class="card" />
</template>
```

```vue [AnimeJS on its own]
<script setup lang="ts">
import { animate } from 'animejs/animation'
import { stagger } from 'animejs/utils'
import type { JSAnimation } from 'animejs'

const cards = useTemplateRef('cards')
let entrance: JSAnimation | undefined

onMounted(() => {
  if (!cards.value) return
  entrance = animate(cards.value, {
    translateY: [16, 0],
    opacity: [0, 1],
    delay: stagger(80),
  })
})

onBeforeUnmount(() => entrance?.revert())
</script>

<template>
  <button @click="entrance?.restart()">Replay</button>
  <div v-for="n in 4" :key="n" ref="cards" class="card" />
</template>
```

```vue [@hypernym/nuxt-anime]
<script setup lang="ts">
import type { AnimeInstance } from 'animejs'

const { $anime } = useNuxtApp()

const cards = useTemplateRef('cards')
let entrance: AnimeInstance | undefined

onMounted(() => {
  if (!cards.value) return
  entrance = $anime({
    targets: cards.value,
    translateY: [16, 0],
    opacity: [0, 1],
    delay: $anime.stagger(80),
  })
})

onBeforeUnmount(() => cards.value && $anime.remove(cards.value))
</script>

<template>
  <button @click="entrance?.restart()">Replay</button>
  <div v-for="n in 4" :key="n" ref="cards" class="card" />
</template>
```
::

[`useAnimate`](/composables/use-animate) waits for the cards to mount, so
nothing runs on the server. It reverts the animation when the component
unmounts. The module registers every composable as an auto-import, so the
component imports only `stagger`.

## How do lists animate in and out?

[`<AnimeTransitionGroup>`](/components/transitions#lists) animates items
that enter and leave a `v-for` list. AnimeJS
[layout](/composables/use-anime-layout) slides the other items to their
new places. Each tab scales items in and out:

::render-code-block-preview
---
code: false
src: examples/comparison/TransitionListDemo.vue
---
::

::code-group
```vue [nanime]
<script setup lang="ts">
const items = ref([1, 2, 3, 4, 5])
</script>

<template>
  <AnimeTransitionGroup
    tag="ul"
    enter-animation="scale"
    leave-animation="scale"
    class="relative"
  >
    <li v-for="item in items" :key="item">{{ item }}</li>
  </AnimeTransitionGroup>
</template>
```

```vue [AnimeJS on its own]
<script setup lang="ts">
import { animate } from 'animejs/animation'

const items = ref([1, 2, 3, 4, 5])

function onEnter(el: Element, done: () => void) {
  animate(el, {
    opacity: [0, 1],
    scale: [0.85, 1],
    duration: 300,
    ease: 'out(3)',
    onComplete: done,
  })
}

function onLeave(el: Element, done: () => void) {
  animate(el, {
    opacity: 0,
    scale: 0.85,
    duration: 200,
    ease: 'in(3)',
    onComplete: done,
  })
}
</script>

<template>
  <TransitionGroup tag="ul" :css="false" @enter="onEnter" @leave="onLeave">
    <li v-for="item in items" :key="item">{{ item }}</li>
  </TransitionGroup>
</template>
```

```vue [@hypernym/nuxt-anime]
<script setup lang="ts">
const { $anime } = useNuxtApp()

const items = ref([1, 2, 3, 4, 5])

function onEnter(el: Element, done: () => void) {
  $anime({
    targets: el,
    opacity: [0, 1],
    scale: [0.85, 1],
    duration: 300,
    easing: 'easeOutCubic',
    complete: done,
  })
}

function onLeave(el: Element, done: () => void) {
  $anime({
    targets: el,
    opacity: 0,
    scale: 0.85,
    duration: 200,
    easing: 'easeInCubic',
    complete: done,
  })
}
</script>

<template>
  <TransitionGroup tag="ul" :css="false" @enter="onEnter" @leave="onLeave">
    <li v-for="item in items" :key="item">{{ item }}</li>
  </TransitionGroup>
</template>
```
::

The other two tabs use Vue's `<TransitionGroup>` with `:css="false"`.
Its `@enter` and `@leave` hooks start an animation and call `done` when it
completes. Vue animates moves only through a CSS move class, so the other
items jump to their new places. Smooth moves take hand-written FLIP code.

## How do the other Nuxt modules compare?

| | `nanime` | `@hypernym/nuxt-anime` |
| :-- | :-- | :-- |
| AnimeJS version | [v4]{.comparison-good} | v3 |
| Latest release | [Sep 2026]{.comparison-good} | Sep 2023 |
| [Auto-imports](/getting-started/installation) | Yes | Opt-in |
| Safe during SSR, cleans up on unmount | [Yes]{.comparison-good} | Manual |
| Rebuilds when a `ref` changes | [Yes]{.comparison-good} | No |
| Keeps the playhead on rebuild | [Yes]{.comparison-good} | No |
| [Animate](/composables/use-animate), [timeline](/composables/use-anime-timeline), [SVG helpers](/composables/utilities#proxies) | Yes | Yes |
| [WAAPI](/composables/use-waapi-animate), [draggable](/composables/use-draggable), [text](/composables/use-split-text), [scroll](/composables/use-anime-scroll), [layout](/composables/use-anime-layout) and more | [Yes]{.comparison-good} | No |
| [Transition components](/components/transitions) | [Yes]{.comparison-good} | No |

::tip
Green marks the better answer in each row. "Manual" means the module
leaves that step to your own code.
::

[`@hypernym/nuxt-anime`](https://github.com/hypernym-studio/nuxt-anime)
is a Nuxt module for AnimeJS v3. It provides the v3 `anime` function as
`$anime`. With `composables: true`, it also auto-imports the same function
as `useAnime`. Each component guards against SSR and cleans up on its own.

AnimeJS v4 replaced `anime()` with separate functions like `animate()` and
`createTimeline()`, and moved them into modules. Code written against v3
needs changes before it runs on v4.

[`nuxt-animejs`](https://www.npmjs.com/package/nuxt-animejs)
is an older module for Nuxt 2, built on a `v-anime` directive. Its README
says it is no longer maintained and points to `@hypernym/nuxt-anime`.

## Which should you pick?

- Pick `nanime` for a Nuxt app on AnimeJS v4, especially one that
  animates lists or values that change.
- Pick AnimeJS on its own for one or two animations that never change.
- Pick `@hypernym/nuxt-anime` for an app that runs on AnimeJS v3 and is
  not moving to v4 yet.
- Pick a package from [Compared with Vue packages](/getting-started/vs-vue-packages)
  for a Vue app without Nuxt.
