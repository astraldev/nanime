This page compares `nanime` with using AnimeJS on its own in Nuxt, and with
the other Nuxt modules for AnimeJS. The `nanime` maintainers wrote it, and
the facts come from each package's source and README as of September 2026.
If something is wrong or out of date,
[open an issue](https://github.com/astraldev/nanime/issues).
For Vue packages, see [vs Vue packages](/getting-started/vs-vue-packages).

## Why nanime?

- **Built for AnimeJS v4.** One composable per v4 API: animate, WAAPI,
  animatable, timeline, draggable, split text, scramble text and scroll.
- **Nuxt-native.** Composables are auto-imported, AnimeJS modules are
  pre-bundled by Vite, and defaults like
  [`keepTime`](/getting-started/configuration) live in `nuxt.config.ts`.
- **SSR safe by default.** Nothing touches the DOM until the target
  mounts, and every instance reverts when its component unmounts.
- **Reactive.** Pass a getter as parameters and the animation rebuilds
  when a `ref` inside it changes, from where the old one was if you ask.
- **Nothing hidden.** Each composable returns the AnimeJS instance itself,
  so the AnimeJS docs apply to it line for line.
- **Small.** The runtime depends on `animejs` and `defu`, nothing else.

## What does nanime add over AnimeJS on its own?

AnimeJS works in Nuxt without any wrapper. The cost is lifecycle code in
every component that animates. Each tab staggers a row of cards in on
mount, with a button that replays it, like the preview:

::code-group
```vue [nanime]
<script setup lang="ts">
import { stagger } from '#nanime/utils'

const cards = useTemplateRef('cards')

const entrance = useAnimate(cards, {
  translateY: [16, 0],
  opacity: [0, 1],
  delay: stagger(80),
})
</script>

<template>
  <button @click="entrance.restart()">Replay</button>
  <div v-for="n in 4" :key="n" ref="cards" class="card" />
</template>
```

```vue [AnimeJS on its own]
<script setup lang="ts">
import { animate } from 'animejs/animation'
import { stagger } from 'animejs/utils'
import type { JSAnimation } from 'animejs'

const cards = useTemplateRef('cards')
let entrance: JSAnimation | undefined

onMounted(() => {
  if (!cards.value) return
  entrance = animate(cards.value, {
    translateY: [16, 0],
    opacity: [0, 1],
    delay: stagger(80),
  })
})

onBeforeUnmount(() => entrance?.revert())
</script>

<template>
  <button @click="entrance?.restart()">Replay</button>
  <div v-for="n in 4" :key="n" ref="cards" class="card" />
</template>
```

```vue [@hypernym/nuxt-anime]
<script setup lang="ts">
import type { AnimeInstance } from 'animejs'

const { $anime } = useNuxtApp()

const cards = useTemplateRef('cards')
let entrance: AnimeInstance | undefined

onMounted(() => {
  if (!cards.value) return
  entrance = $anime({
    targets: cards.value,
    translateY: [16, 0],
    opacity: [0, 1],
    delay: $anime.stagger(80),
  })
})

onBeforeUnmount(() => cards.value && $anime.remove(cards.value))
</script>

<template>
  <button @click="entrance?.restart()">Replay</button>
  <div v-for="n in 4" :key="n" ref="cards" class="card" />
</template>
```
::

[`useAnimate`](/composables/use-animate) waits for the cards to mount, so
nothing runs on the server. It reverts the animation when the component
unmounts. The module registers every composable as an auto-import, so the
component imports only `stagger`.

The gap widens once a value changes. Here a slider sets how far a box
travels. `nanime` takes a getter and rebuilds on its own. With `keepTime`,
the box carries on from where it was instead of jumping back to the start.

::code-group
```vue [nanime]
<script setup lang="ts">
const box = useTemplateRef('box')
const distance = ref(200)

useAnimate(box, () => ({
  translateX: distance.value,
  loop: true,
  alternate: true,
}), { keepTime: true })
</script>

<template>
  <input v-model.number="distance" type="range" max="400">
  <div ref="box" class="box" />
</template>
```

```vue [AnimeJS on its own]
<script setup lang="ts">
import { animate, type JSAnimation } from 'animejs/animation'
import { keepTime } from 'animejs/utils'

const box = useTemplateRef('box')
const distance = ref(200)
let animation: JSAnimation | undefined

const build = keepTime((el: HTMLElement) => animate(el, {
  translateX: distance.value,
  loop: true,
  alternate: true,
}))

onMounted(() => {
  if (box.value) animation = build(box.value)
})

watch(distance, () => {
  if (box.value) animation = build(box.value)
})

onBeforeUnmount(() => animation?.revert())
</script>

<template>
  <input v-model.number="distance" type="range" max="400">
  <div ref="box" class="box" />
</template>
```
::

AnimeJS on its own is still a fine choice for one or two animations that
never change.

## How do the other Nuxt modules compare?

|                                               | `nanime` | `@hypernym/nuxt-anime` |
| :-------------------------------------------- | :------- | :--------------------- |
| AnimeJS version                               | v4       | v3                     |
| [Auto-imports](/getting-started/installation) | Yes      | Yes                    |
| Safe during SSR, cleans up on unmount         | Yes      | Manual                 |
| Rebuilds when a `ref` changes                 | Yes      | No                     |
| One composable per AnimeJS API                | Yes      | No                     |
| Latest release                                | Sep 2026 | Sep 2023               |

"Manual" means the module leaves that step to your own code.

[`@hypernym/nuxt-anime`](https://github.com/hypernym-studio/nuxt-anime)
is a Nuxt module for AnimeJS v3. Its `useAnime` composable is the v3
`anime` function under another name. Each component guards against SSR
and cleans up on its own.

AnimeJS v4 replaced `anime()` with separate functions like `animate()` and
`createTimeline()`, and moved them into modules. Code written against v3
needs changes before it runs on v4.

[`nuxt-animejs`](https://www.npmjs.com/package/nuxt-animejs)
is an older module for Nuxt 2, built on a `v-anime` directive. Its README
says it is no longer maintained and points to `@hypernym/nuxt-anime`.
