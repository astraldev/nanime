Each section below shows the 0.3 code that breaks in `nanime` 0.4 and
what to write instead. No other change is required. The
[changelog](/changes/changelog) lists everything else that is new.

## Replace `keepTime` with `rebuild`

The `keepTime` option is now `rebuild`, which takes `'restart'`,
`'keepTime'` or `'keepValue'`. `keepTime: true` becomes
`rebuild: 'keepTime'`, and `keepTime: false` becomes `rebuild: 'restart'`,
which is the default.

::code-group
```ts [0.3 nuxt.config.ts]
export default defineNuxtConfig({
  nanime: {
    keepTime: true,
  },
})
```

```ts [0.4 nuxt.config.ts]
export default defineNuxtConfig({
  nanime: {
    rebuild: 'keepTime',
  },
})
```
::

The build logs a warning while `keepTime` is still set in
`nuxt.config.ts`. It does not check `runtimeConfig.public.nanime.keepTime`,
and 0.4 ignores it. Rename it to `runtimeConfig.public.nanime.rebuild`.
The option a composable takes as its last argument is renamed the same
way:

::code-group
```ts [0.3]
useAnimate(box, { x: () => x.value }, { keepTime: true })
```

```ts [0.4]
useAnimate(box, { x: () => x.value }, { rebuild: 'keepTime' })
```
::

A `keepTime` option left in a composable call is a type error in
TypeScript. In plain JavaScript it does nothing, and the composable
restarts on every rebuild. Search the project for `keepTime` to find each
one.

`'keepValue'` is new and works in `useAnimate` only. The other
composables treat it as `'restart'`.
[`useAnimate`](/composables/use-animate)
explains what each value does.

## Rename `NanimeAppConfig` to `NanimeConfig`

The type of the `nanime` key in `app.config.ts` is now `NanimeConfig`.
Update every import from `#nanime/types` or `nanime/vue`:

::code-group
```ts [0.3]
import type { NanimeAppConfig } from '#nanime/types'
```

```ts [0.4]
import type { NanimeConfig } from '#nanime/types'
```
::

## Check nested `provideAnimeDefaults()` calls

Each of `transition`, `transitionGroup` and `layoutGroup` in
`provideAnimeDefaults()` now replaces the same one from a call in a parent
component as a whole. In 0.3 the two were merged prop by prop.

::code-group
```ts [Outer call]
provideAnimeDefaults({
  transition: { enterAnimation: 'fade', mode: 'out-in' },
})
```

```ts [Inner call]
provideAnimeDefaults({
  transition: { enterAnimation: 'scale' },
})
```
::

In 0.3 a transition inside the inner component entered with `scale` and
used `mode: 'out-in'`. In 0.4 it enters with `scale` and takes `mode` from
`app.config.ts`, because the inner `transition` replaces the outer one. To
keep `out-in` there, set `mode` in the inner `transition`.

A key the inner call leaves out keeps the outer value. An inner call that
sets only `transitionGroup` keeps the outer `transition`.
[Defaults](/guides/defaults#scope-defaults-to-part-of-the-app) shows the
full order.

## Check `layoutOptions`

A `layoutOptions` object now replaces the `layoutOptions` set in
`provideAnimeDefaults()` or `app.config.ts` whole, instead of merging
keys. The same holds when `provideAnimeDefaults()` overrides
`app.config.ts`.

::code-group
```ts [app.config.ts]
export default defineAppConfig({
  nanime: {
    components: {
      layoutGroup: { layoutOptions: { duration: 400, ease: 'out(3)' } },
    },
  },
})
```

```vue [Component]
<AnimeLayoutGroup :deps="[view]" :layout-options="{ duration: 200 }" />
```
::

In 0.3 this group animated with `duration: 200` and `ease: 'out(3)'`. In
0.4 it uses `duration: 200` and AnimeJS's default ease, because the prop
replaces the whole `layoutOptions` object. Repeat `ease` in the prop to
keep the old result.

## Adopt the new features

None of these are required:

- Pass [`animation`](/components/transition) to set a transition's enter and
  leave with one prop.
- Set the motion of the whole app from one object with a
  [preset](/guides/presets).
- Set default parameters for `useAnimate` and `useDraggable` in
  [Defaults](/guides/defaults).
- Use [`nanime/vue`](/guides/vue) in a Vue 3 app without Nuxt.
- Pass `waapi` to a transition component to run it on the Web Animations
  API.
