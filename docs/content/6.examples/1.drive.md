Switch the layout, filter, sort, expand a tile, or drag one onto Trash and
undo it. The numbered controls work, and the greyed ones are decoration.

## Built with

- [`<AnimeTransitionGroup>`](/components/transition): the tiles, as they
  enter, leave and move
- [`<AnimeLayoutGroup>`](/components/layout-group): the sliding highlight
  in each segmented control
- [`<AnimeTransition>`](/components/transition): a tile dropped in the
  trash, the trash badge and the undo notice
- [`useDraggable`](/composables/use-draggable): dragging a tile and
  springing it back
- [`useAnimatable`](/composables/use-animatable): the tile filling the
  trash and the storage bar
- `spring` from [`#nanime/easings`](/composables/utilities), and `stagger`
  and `round` from [`#nanime/utils`](/composables/utilities)

## Layout switches are class changes

The grid is an [`<AnimeTransitionGroup>`](/components/transition) whose
classes change with the layout. The group records every element before an
update and animates the difference afterwards, so the icon and name move
with their tile.

```vue
<AnimeTransitionGroup
  tag="ul"
  :class="groupClasses[layout]"
  :move-animation="{ duration: 300, delay: stagger(8), ease: 'out(3)' }"
>
  <DriveTile v-for="file in files" :key="file.id" :file="file" />
</AnimeTransitionGroup>
```

Filtering and sorting come from one `computed` that returns a filtered,
sorted copy of the files. Moves have no overshoot, because the tiles are
already on screen. New tiles pop in on a `spring()` instead.

## The pill is one element

The highlight behind a segmented control is a single element in the same
grid row as the buttons. Its `grid-column` follows the selected value, and
an [`<AnimeLayoutGroup>`](/components/layout-group) slides and resizes it.
Only the pill is listed in `elements`, so the buttons stay where they are.

```vue
<AnimeLayoutGroup :deps="[selected]" elements=".segment-pill">
  <span class="segment-pill" :style="{ gridColumn: segments.findIndex(s => s.value === selected) + 1 }" />
</AnimeLayoutGroup>
```

## The drop test follows the pointer

A list row is as wide as the grid, so its centre never reaches the
sidebar. `onUpdate` adds the draggable's `x` and `y` to the point where the
handle was grabbed and tests that point against the trash. A tile released
anywhere else springs back through `snap: [0]` and a `spring()` as
`releaseEase`.

::collapsible{name="More detail"}
**State.** One composable, `useDrive`, holds the files, the trash, the
layout, the filter, the sort order and the expanded tile. Each part of the
window only gets the props and events it needs.

**Expanded tiles.** An expanded tile gets `col-span-2 row-span-2` in the
grid and a bigger height in the other layouts, and its neighbours move out
of the way. Removed tiles fade and shrink to `0.95` in 150ms.

**The trash fill.** The fill is one number from `0` to `1`, run by
[`useAnimatable`](/composables/use-animatable) over 250ms. The card's
width, height and offset are interpolated from it. At `1` the card covers
the trash, less 6px of padding, whether the tile started as a grid square
or a full-width row. An animatable starts from its current value, so a tile
that crosses in and out of the trash quickly never jumps. `onGrab` measures
the trash, the tile's size and its rest centre once.

**Dropping.** On release over the trash, `onRelease` calls
`draggable.stop()` to cancel the return spring and hides the handle. The
handle sits in an [`<AnimeTransition>`](/components/transition), so it
fades out first. The file leaves the list only in `@after-leave`, because
removing it earlier unmounts the tile, and `useDraggable` reverts on
unmount, which moves the card back to its slot before it fades.

The tiles read the trash element through a getter instead of a prop value.
A prop that changed from `null` to the element after mount would re-render
the list and run a layout pass over every tile.

**Sidebar and toast.** The trash badge is keyed on the count inside an
`<AnimeTransition mode="out-in">`, so every new count pops in. The storage
bar and its number read from one object animated by `useAnimatable`, which
retargets from its current value when the total changes mid-animation. The
undo notice is keyed on the file id, so trashing a second file swaps the
notice instead of stacking a new one.

**Highlights.** Each live control has a `data-live` attribute, and a
`::after` rule prints it with `attr()`. That makes the numbered badges.
