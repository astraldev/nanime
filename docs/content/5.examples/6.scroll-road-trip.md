## What's happening

The scroll position drives the car directly, like a playhead: it only moves
while you scroll the panel, and stops the instant you stop.

The view looks straight down at the road, so the car's heading is the
tangent of the curve, turning with every bend but never tilting as it would
on a real slope. A trail traces the line the car has covered.

The observer reads the panel's own scroll, not the page's, so scrolling the
page itself never moves the car.

## How it's built

The scroll observer comes from `useAnimeScroll`, which returns a proxy over
it. Passed as an animation's `autoplay`, that proxy scrubs the animation to
the observer's progress instead of letting it advance on its own. `sync:
true` locks it to the scroll position, with no easing or lag.

`container` and `axis: 'x'` point the observer at the panel's own horizontal
scroll instead of the page's vertical one. `target`, `enter: 'left left'`,
and `leave: 'right right'` set the range: it runs from the scene's left edge
meeting the panel's left edge to its right edge meeting the panel's right,
one full sweep of the scrollbar.

`createMotionPath(pathElement)` from
[`#nanime/proxies/svg`](/misc/proxies) returns `translateX`, `translateY`,
and `rotate` sampled along the road, so spreading it into the animation's
parameters gives both position and heading from one source. The car sits
centred on the origin, since a motion path displaces an element rather than
repositioning its box.

The trail is a separate copy of the road path, wrapped in `createDrawable`.
Animating its `draw` property from `'0 0'` to `'0 1'` reveals it end to end.
It needs its own observer, since a single observer drives only one
animation.

## Building it yourself

1. Put a wide element inside a panel with `overflow-x: auto`, so the panel scrolls sideways while the page does not.
2. Draw the road as a `<path>` with gentle `C`/`S` curves. A straight line hides the rotation entirely, so the winding is the point.
3. Draw the car viewed from above, centred on the origin. Give it `transform-box: fill-box` and `transform-origin: 50% 50%` so it pivots about its own middle. Keep it in its own component so the scene markup stays readable.
4. Create an observer with `useAnimeScroll`, passing the parameters as a getter so it rebuilds once the template refs resolve:

   ```ts
   useAnimeScroll(() => ({
     container,
     target,
     axis: 'x',
     enter: 'left left',
     leave: 'right right',
     sync: true,
   }))
   ```

5. Animate the car with `{ ...createMotionPath(pathElement), ease: 'linear', autoplay: scrollObserver }`. Keep the ease linear, or the scrub will drift from the scrollbar.
6. Give the trail its own observer with the same parameters. Each observer can drive only one animation, so reusing the car's would move it over to the trail instead.
7. Wrap the trail element in `createDrawable` and take `[0]` from the array it returns. Pass that to `useAnimate` with `draw: ['0 0', '0 1']` to reveal the trail end to end.
8. Read progress from the observer's `onUpdate` callback. Compare each value to the last to tell which way the scrollbar is moving.

::warning
Read `.value` off each template ref yourself before passing it in. Only the
parameters object is unwrapped, and AnimeJS resolves no framework refs.
Passing a ref directly leaves both `container` and `target` falling back to
`document.body`. When comparing `onUpdate` progress values, ignore
differences under about `0.0005`, or jitter at rest flips the reading.
::
