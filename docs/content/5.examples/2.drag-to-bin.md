## What's happening

Dragging a card toward the bin shrinks and slides it as it gets close. Dropped
inside, it fades out and the list closes the space it left. If you pull it back
out before releasing, it returns to its normal size.

## How it's built

[`useDraggable`](/composables/use-draggable) moves the card and handles the
return trip. Setting `snap: [0]` with
`releaseEase: spring({ bounce: 0.2, duration: 500 })` springs a card back to
its origin when released outside the bin, with no release handler needed.

The shrink runs off [`useAnimatable`](/composables/use-animatable). Being over
the bin is a state rather than a gradient. In `onUpdate`, testing the handle's
centre against the bin's box reports a boolean, and the animatable eases a
`0 → 1` value from it over 350ms. Width, height, and offset interpolate from
that single value in a computed style, so the inside-the-bin look is one
animation instead of three.

Everything else is CSS. The bin's highlight is a class toggled from that
boolean. A binned card fades on an opacity transition, while the ghost element
collapses its height and margin. The list below is not animated at all. It moves
because the collapsing ghost is in normal flow, so the browser reflows what sits
under it.

Nothing is positioned by hand. Each card sits inside a ghost element to hold
its place in the flow. The drag handle is absolutely positioned within the
ghost, and the visible card fills the handle, so dragging never disturbs the
surrounding layout.

The card is split in two. A fixed-size handle is what `useDraggable` moves, and
the visible card inside it changes shape. That keeps the drag target's box
constant. Anime.js watches draggables with a `ResizeObserver` and recalculates
whenever their size changes, so a constant box avoids extra recalculations.

On release, the only work left is bookkeeping. If the card was over the bin,
`draggable.stop()` halts it and the parent marks the item binned. Restoring
resets the blend value and calls `draggable.reset()`.

::note
Geometry is measured once in `onGrab`, not on every frame. Nothing in the list
moves until the card is released, so a per-frame `getBoundingClientRect()` would
trigger layout reflows and return identical values.
::

## Building it yourself

1. Wrap each item in a ghost element that stays in normal flow. This preserves the list position and lets the list reflow when a card is removed.
2. Inside the ghost, position a fixed-size handle absolutely, and size the visible card to fill it. Only the handle is dragged.
3. Call `useDraggable(handle, { onGrab, onUpdate, onRelease })`. In `onGrab`, measure the ghost's rest rect and the bin's rect once, and compute the size delta between them.
4. In `onUpdate`, test whether the handle's centre falls inside the bin's rect, and report that boolean only when it changes.
5. Drive a [`useAnimatable`](/composables/use-animatable) value from `0` to `1` off that boolean, and interpolate width, height, and offset from it in a computed style.
6. Give the draggable `snap: [0]` and a `releaseEase` spring, so a card dropped outside the bin returns on its own.
7. On release, if the boolean was true, stop the draggable and mark the item binned. Collapse the ghost's height and margin with a CSS transition to close the gap.
8. To restore, set the blend value back to `0` and call `draggable.reset()`.
