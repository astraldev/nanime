A terminal-style build log with eight steps. Run build starts it, and it
can be paused, resumed and reset while it runs. The status line below the
log names the current step and the next one.

## What's happening

The bottom line of the terminal shows the current step. Its text scrambles
through random characters before it settles on the step's name. A spinner
turns next to it. When a step finishes, its name moves up into the log with
a checkmark. The log keeps the last three steps. The oldest fades out at
the top while the rest slide up.

Pausing stops the spinner and the step timer, and a `[paused]` badge fades
in. The spinner carries on from the same angle on resume. After the last
step, the spinner shrinks away and a checkmark pops in with a small
overshoot.

## How it's built

Each step writes its text to the status line, which
[`useScrambleText`](/composables/use-scramble-text) watches. A new text
starts a new scramble, so the sequence never triggers one directly.

A `setTimeout` chain moves from step to step. Each step waits for its
scramble to finish, then for its own delay. The scramble reveals one
character every 20ms (`revealRate: 50`) and settles for 300ms, so the
timer waits `(length - 1) * 20 + 300` for the new text, plus the delay.
AnimeJS times the scramble on the longer of the old and new text. When
the new text is shorter, the scramble ends a few characters later, inside
the delay.

Pausing clears the timer. Resuming starts the current step's full wait
again, not the part that was left.

The spinner turns through
[`useWaapiAnimate`](/composables/use-waapi-animate), a linear 360° rotation
on a loop. WAAPI runs it off the main thread, and `pause()` and `play()`
hold its angle across a pause.

The finished steps are a `v-for` inside
[`<AnimeTransitionGroup>`](/components/transitions). The list shows the
last three, so each new step adds a line at the bottom and removes the
oldest at the top. New lines rise `10px` into place on a `spring()` ease.
The leaving line fades out while AnimeJS
[layout](https://animejs.com/documentation/layout) slides the others up, on
a spring as well.

The icon beside the status line is one
[`<AnimeTransition>`](/components/transitions) with `mode="out-in"` around
three `v-if` branches: a caret while idle, the spinner while running and a
checkmark when done. The old icon shrinks out before the new one springs
in. The `[paused]` badge uses a plain `<AnimeTransition>` and its default
fade.

## Building it yourself

1. Define the steps as an array of `{ label, delay }`.
2. Track the state as `'idle' | 'running' | 'done'`, plus a paused flag, the current step index and the status text.
3. Bind the status line to [`useScrambleText`](/composables/use-scramble-text) with a getter that returns `{ text, chars: '0123456789abcdef', settleDuration: 300, revealRate: 50 }`.
4. Advance with a `setTimeout` chain. Each step sets the index and the text, then waits `(text.length - 1) * 20 + 300` plus its delay.
5. Pause by clearing the timer and calling `pause()` on the spinner. Resume by calling `play()` and scheduling the current step's full wait again.
6. Render the finished steps with a `computed` that slices the last three, inside `<AnimeTransitionGroup>` with spring `enterAnimation` and `moveAnimation`, and a short fade for `leaveAnimation`.
7. Swap the status icon with `<AnimeTransition mode="out-in">` around `v-if` branches for each state. Put the spinner's template ref on an inner element, and turn it with [`useWaapiAnimate`](/composables/use-waapi-animate).
8. Clear the timer in `onBeforeUnmount`.
