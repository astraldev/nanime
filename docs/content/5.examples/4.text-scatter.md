A paragraph whose letters react to the cursor. Every five seconds the mode
flips between pushing them away and pulling them in. The change shows even while
the cursor holds still.

## What's happening

Every letter is its own element, reacting only once the cursor gets close
enough. Each behaves like an iron filing near a magnet, pushed away or pulled in
depending on the mode. Random jitter prevents a row of letters from moving as
one stiff line. Each letter tumbles and recedes into the page, then eases back
to its starting spot, size, and depth.

## How it's built

[`useSplitText`](/composables/use-split-text) splits the paragraph into one
element per character, since each must move on its own. A continuous timer
drives the distance check rather than the `pointermove` event, so it keeps
running while the cursor holds still. That matters because the mode flips on its
own five-second timer whether the pointer moves or not.

On every tick it walks the characters and skips two kinds: anything outside the
radius, and anything whose current animation is less than 40% complete
(`progress < 0.4`). That second rule stops a held-still cursor from restarting
the same letter's animation on every tick.

Each push is two keyframes. The first is an immediate displacement away from or
toward the pointer. The second is a return to the character's original spot on
`inOutQuad`, delayed by 400ms and eased over 800ms. Because the return always
targets the same rest position, a character never drifts, however often it is
pushed again mid-settle.

Depth comes from `z` (`translateZ`) alongside `x` and `y`, pushed negative so
the character moves away from the viewer. `rotateX` and `rotateY` add the tumble.
All of it scales off the same distance-based force as the push, easing back to
`0` in the return keyframe.

None of it reads as depth without a tight CSS `perspective` on the container. A
large value flattens the effect into a 2D skew, while a smaller one (this demo
uses `400px`) puts the viewer closer to the scene and exaggerates the depth.

Character positions are measured once after the split resolves, then again
only on resize, on scroll, and when the pointer enters the container. A pointer
move alone cannot change the layout, so there is nothing to re-measure.

The halo marking the radius is separate from the letter calculations. The hit
test runs off plain, non-reactive pointer variables, while the halo is
positioned from container-relative refs. This limits reactive work to the one
element that needs it.

## Building it yourself

1. Split the paragraph with [`useSplitText`](/composables/use-split-text)`(el, { chars: true })`.
2. Measure each character's `getBoundingClientRect()` once after the split resolves, and again on resize, scroll, and `pointerenter`, never on pointer move.
3. Keep the pointer coordinates used for hit testing in plain variables, since nothing re-renders from them. Use separate container-relative refs for the halo, which does.
4. Run a continuous `createTimer({ onUpdate })` loop instead of reacting to `pointermove`, so the effect keeps evaluating while the pointer is still.
5. In `onUpdate`, check each character: skip it if outside the radius, or if its animation is less than 40% complete. Animate it with two keyframes. The first displaces it along the line to the pointer, pushes `z` negative, and tilts it with `rotateX` and `rotateY`. The second eases `x`, `y`, `z`, `rotate`, `rotateX`, and `rotateY` back to `0` on `inOutQuad` after a 400ms delay and over 800ms. Give the container a tight `perspective` so the depth reads.
6. Flip a repel and attract mode ref on a `useIntervalFn` every 5 seconds. Nothing else needs to change, since the push vector's sign already reads from it.
