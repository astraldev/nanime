## Try it

The numbered controls work. The greyed ones fill out the page and do
nothing.

1. **Switch the layout** between grid, list and columns. Every tile glides
   to its new place and size, and its icon and name slide with it.
2. **Filter** by kind. The files that don't match shrink away and the rest
   close the gap.
3. **Sort** by name, type or size. The tiles move to their new order.
4. **Click a tile** to expand it, and click again to shrink it. A tile
   dragged anywhere but the trash springs back to its slot.
5. **Drag a tile onto Trash.** When the pointer reaches the bin, the tile
   snaps onto it and resizes to fill it. It fades out when you let go. The
   badge counts up and the storage bar counts down.
6. **Upload** adds a file, which pops in at its sorted place. The button
   turns off at eight files.
7. **Undo** in the notice puts the last trashed file back.

Reset in the title bar puts everything back to the start.

## Built with

- [`<AnimeTransitionGroup>`](/components/transitions): the tiles, as they
  enter, leave and move
- [`<AnimeLayoutGroup>`](/components/layout-group): the sliding highlight
  in each segmented control
- [`<AnimeTransition>`](/components/transitions): a tile dropped in the
  trash, the trash badge and the undo notice
- [`useDraggable`](/composables/use-draggable): dragging a tile and
  springing it back
- [`useAnimatable`](/composables/use-animatable): the tile filling the
  trash and the storage bar
- `spring` from [`#nanime/easings`](/composables/utilities), and `stagger`
  and `round` from [`#nanime/utils`](/composables/utilities)

::collapsible{name="How it's built"}
**State.** One composable, `useDrive`, holds the files, the trash, the
layout, the filter, the sort order and the expanded tile. The window is
split into a title bar, a sidebar, a toolbar, a filter bar, the file grid
and a toast, and each part only gets the props and events it needs.

**Tiles.** The grid is an [`<AnimeTransitionGroup>`](/components/transitions)
whose classes change with the layout: `grid`, `flex flex-col` or
`columns-3`. The group records every element inside it before an update and
animates the difference after it, so a layout switch is only a change of
classes. The icon and name move too, because they are elements inside the
group. Filtering and sorting come from one `computed` that returns a
filtered, sorted copy of the files. The group sees a new order and moves the
tiles into it. An expanded tile gets `col-span-2 row-span-2` in the grid and
a bigger height in the other layouts, and its neighbours move out of the way.

New tiles pop in: they scale up from `0.9` on a `spring()` with a small
bounce, so they overshoot a little and settle. Removed tiles fade and shrink
to `0.95` in 150ms. Moves have no overshoot. The tiles are already on screen,
so they ease out over 300ms with `stagger(8)` as their delay, and each
tile's content trails the tile by a few milliseconds.

**Segmented controls.** The pill behind the current option is one element in
the same grid row as the buttons. Its `grid-column` follows the selected
value. An [`<AnimeLayoutGroup>`](/components/layout-group) with
`:deps="[selected]"` and `elements=".segment-pill"` slides it to the new
column and resizes it to the new button's width. Only the pill is listed in
`elements`, so the buttons stay where they are.

**Dragging to the trash.** Each tile's handle gets
[`useDraggable`](/composables/use-draggable) with `snap: [0]` and a
low-bounce `spring()` as `releaseEase`, so a tile dropped anywhere else
returns to its slot.

The hit test follows the pointer, not the tile. A list row is as wide as
the grid, so its centre would never reach the sidebar. The handle's own
`pointerdown` stores where it was grabbed, and `onUpdate` adds the
draggable's `x` and `y` to that point and tests it against the trash rect.
`onGrab` measures the trash, the tile's size and its rest centre once, since
nothing else moves during a drag.

The fill is one number from `0` to `1`, run by
[`useAnimatable`](/composables/use-animatable) over 250ms. The card's
width, height and offset are interpolated from it. At `0` the card has its
own size. At `1` it covers the trash, less 6px of padding, and sits on its
centre, whether the tile started as a grid square or a full-width row. An
animatable starts from its current value, so a tile that crosses in and out
of the trash quickly never jumps.

On release over the trash, `onRelease` calls `draggable.stop()` to cancel
the return spring and hides the handle. The handle sits in an
[`<AnimeTransition>`](/components/transitions), so it fades out first.
The file leaves the list only in `@after-leave`. Removing it earlier would
unmount the tile, and `useDraggable` reverts its draggable on unmount,
which moves the card back to its slot before it fades.

The tiles read the trash element through a getter instead of a prop value.
The element only exists after mount, and a prop that changed from `null` to
the element would re-render the list and run a layout pass over every tile.

**Sidebar and toast.** The trash badge is keyed on the count inside an
`<AnimeTransition mode="out-in">`, so every new count pops in.
The storage bar and its number read from one object animated by
`useAnimatable`, which retargets from its current value when the total
changes again mid-animation. The undo notice is keyed on the file id, so
trashing a second file swaps the notice instead of stacking a new one.

**Highlights.** The numbered badges are plain CSS: each live control has a
`data-live` attribute, and a `::after` rule prints it with `attr()`.
