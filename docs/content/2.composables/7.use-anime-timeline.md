`useAnimeTimeline` wraps the [createTimeline](https://animejs.com/documentation/timeline){target="_blank"}
function from AnimeJS. It plays a sequence of animations on one clock, so
the whole sequence plays, pauses and seeks together.

When reactive parameters change, `nanime` rebuilds the timeline and adds the
same steps again. By default it restarts. Set `keepTime: true` to carry the
playhead over instead.

## Usage

## Signature

```ts
function useAnimeTimeline(
  parameters?: MaybeRefOrGetter<TimelineParams>,
  options?: NanimeInstanceOptions
): BufferedProxyReturns<Timeline>
```

## Parameters

::field-group
  :::field{name="parameters" type="MaybeRefOrGetter<TimelineParams>"}
  Accepts a plain object, a `ref` or a getter. The timeline rebuilds when it
  changes. See the
  [AnimeJS timeline documentation](https://animejs.com/documentation/timeline){target="_blank"}
  for the options.

  ::::note
  A `useAnimeScroll` result can go straight into `autoplay`. `nanime` passes
  AnimeJS the observer inside it.
  ::::
  :::

  :::field{name="options" type="NanimeInstanceOptions"}
  How the timeline behaves when it rebuilds.

  | Option | Type | Default |
  | :--- | :--- | :--- |
  | `keepTime` | `boolean`{lang="ts-type"} | `false` |
  :::
::

## Returns

Returns a buffered proxy around the AnimeJS `Timeline`{lang="ts-type"}.
Its methods and properties are in the
[AnimeJS timeline documentation](https://animejs.com/documentation/timeline){target="_blank"}.
The members `nanime` changes:

| Member | Type | Notes |
| :--- | :--- | :--- |
| `add(targets, params, position?)` | `(...) => this`{lang="ts-type"} | `targets` also accepts template refs and component refs. Runs again on every rebuild. |
| `set(targets, params, position?)` | `(...) => this`{lang="ts-type"} | `targets` also accepts template refs and component refs. Runs again on every rebuild. |
| `remove(targets, propertyName?)` | `(...) => this`{lang="ts-type"} | `targets` also accepts template refs and component refs. Runs again on every rebuild. |
| `sync(animation, position?)` | `(...) => this`{lang="ts-type"} | `animation` also accepts the value returned by `useAnimate` or `useWaapiAnimate`. Runs again on every rebuild. |
| `label()`, `call()`, `stretch()` | `(...) => this`{lang="ts-type"} | Run again on every rebuild. |

The timeline is created when the component mounts. Methods can be called
straight from `setup()`, and run at that point. Playback methods such as
`play()` run once and are not repeated on a rebuild. Read properties such
as `currentTime` [after mount](#read-properties-after-mount).

## Caveats

### Read properties after mount

```ts
// wrong: currentTime is undefined before mount
const tl = useAnimeTimeline()
console.log(tl.currentTime) // undefined

// right: read timeline properties after mount
onMounted(() => {
  console.log(tl.currentTime)
})
```

The underlying `Timeline` instance is created after mount, or immediately
in [Instant mode](/composables/introduction#instant-play). Chainable
methods such as `add()`, `play()`, and `pause()` buffer safely before
that and replay in sequence, but non-chainable property reads return
`undefined` until the timeline instance exists. Access inspection properties
after mount.
