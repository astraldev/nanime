`useAnimate` wraps the [animate](https://animejs.com/documentation/animation)
function from AnimeJS. It animates DOM elements, SVG nodes, and JavaScript
objects.

When reactive parameters change, `nanime` rebuilds the underlying animation.
By default it restarts. Set `keepTime: true` to carry the playhead over so
playback continues instead.

## Usage

## Signature

```ts
function useAnimate(
  target: AnimeTargets,
  parameters?: MaybeRefOrGetter<AnimationParams>,
  options?: NanimeInstanceOptions
): JSAnimation
```

## Parameters

::field-group
  :::field{required name="target" type="AnimeTargets"}
  Target element, SVG node, plain JavaScript object, or array of targets.
  Accepts CSS selectors, DOM elements, and component or template refs.
  :::

  :::field{name="parameters" type="MaybeRefOrGetter<AnimationParams>"}
  Animation parameters including animatable properties, duration, delay,
  easing, and playback callbacks.

  | Option      | Type                                      | Default    |
  | :---------- | :---------------------------------------- | :--------- |
  | `duration`  | `number \| FunctionValue`{lang="ts-type"} | `1000`     |
  | `delay`     | `number \| FunctionValue`{lang="ts-type"} | `0`        |
  | `ease`      | `EasingParam`{lang="ts-type"}             | `'out(2)'` |
  | `loop`      | `number \| boolean`{lang="ts-type"}       | `0`        |
  | `alternate` | `boolean`{lang="ts-type"}                 | `false`    |
  :::

  :::field{name="options" type="NanimeInstanceOptions"}
  Instance options controlling rebuild and lifecycle behaviour.

  | Option     | Type      | Default |
  | :--------- | :-------- | :------ |
  | `keepTime` | `boolean` | `false` |
  :::
::

## Returns

Returns a reactive proxy around the AnimeJS `JSAnimation`
instance, so every method and property it has (`play`, `pause`, `restart`,
`revert`, `cancel`, `seek`, `progress`, `duration`, and the rest) is
available on it. See the
[AnimeJS animate documentation](https://animejs.com/documentation/animation)
for the full surface. Two things work differently through this proxy:

- Methods are destructuring-unsafe. See the
  [destructuring caveat](#do-not-destructure-the-returned-instance).
- Properties like `progress` and `duration` do not trigger Vue template
  re-renders. See the
  [template reactivity caveat](#progress-and-playback-properties-do-not-update-templates).

## Caveats

### Plain object targets must be reactive or shallowReactive

```ts
// wrong: AnimeJS writes to the object's properties directly, bypassing .value
const position = ref({ x: 0, y: 0 })
useAnimate(position, { x: 100 })

// right: AnimeJS animates reactive object properties directly
const position = reactive({ x: 0, y: 0 })
useAnimate(position, { x: 100 })
```

Passing a `ref` holding an object fails because AnimeJS writes
directly to properties on the target without touching `.value`. The mutations
bypass Vue's reactivity system and the template never updates. Wrap plain
objects in `reactive` or `shallowReactive`
instead so property updates trigger re-renders.

### Do not destructure the returned instance

```ts
// wrong: copies methods once, losing the link on rebuild
const { play } = useAnimate('.target', { opacity: 0 })

// right: calls play on the active proxy
const animation = useAnimate('.target', { opacity: 0 })
animation.play()
```

Destructuring properties or methods off the returned proxy binds them to the
initial instance. When reactive parameters change and rebuild the animation,
destructured functions continue targeting the discarded instance. Retain the
proxy object and invoke methods directly on it.

### Progress and playback properties do not update templates

```ts
// wrong: progress never updates inside a template interpolation
// <p>{{ animation.progress }}</p>

// right: update a ref inside onUpdate
const progress = ref(0)
const animation = useAnimate('.target', {
  opacity: [0, 1],
  onUpdate: self => progress.value = self.progress,
})
```

Interpolating properties like `progress` in a template displays only their
initial value. AnimeJS updates them outside Vue's reactivity tracking, so
nothing triggers a re-render. Assign the current value to a
`ref` inside the `onUpdate` callback to drive reactive
template elements.
