`useSplitText` wraps [`splitText()`](https://animejs.com/documentation/text)
from AnimeJS. It splits the text again when `target`, a parameter or `html`
changes, keeps effects added with `addEffect()` across each split, and
restores the original text when the component unmounts.

## API

```ts
function useSplitText(
  target: MaybeRef<SplitTextTargets>,
  parameters?: MaybeRefOrGetter<TextSplitterParams>,
  options?: SplitTextOptions
): SplitText
```

::field-group
  :::field{name="target" type="MaybeRef<SplitTextTargets>" required}
  Text container element. Accepts CSS selectors, DOM elements, and template
  refs.
  :::

  :::field{name="parameters" type="MaybeRefOrGetter<TextSplitterParams>"}
  Accepts a plain object such as `{ chars: true }`, a `ref` or a getter. The
  text is split again when a value in it changes. See the
  [AnimeJS splitText documentation](https://animejs.com/documentation/text)
  for the options.
  :::

  :::field{name="options" type="SplitTextOptions"}
  `html` takes `MaybeRefOrGetter<string | null | undefined>`{lang="ts-type"} and
  defaults to the target's own content. It is the text to split. When it
  changes, the new text is split in place. While it is `null` or `undefined`,
  the current text stays and a warning is logged in development. Render the
  element [with](#render-changing-text-with-v-once) [`v-once`](#render-changing-text-with-v-once) when you use it.
  :::
::

Returns a plain object of refs and computed getters. Destructuring is safe.

| Member                    | Type                                           | Notes                                                                                                              |
| ------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `lines`, `words`, `chars` | `Ref<HTMLElement[]>`{lang="ts-type"}           | The split elements, [empty until mount](#arrays-are-empty-during-setup).                                           |
| `properties`              | `ComputedRef`{lang="ts-type"}                  | Non-function properties of the underlying splitter, except `lines`, `words` and `chars`. `undefined` before mount. |
| `methods`                 | `ComputedRef<SplitterMethods>`{lang="ts-type"} | Splitter methods (`revert`, `split`, `refresh`), with `addEffect` wrapped to persist. `undefined` before mount.    |
| `refresh()`               | `() => void`{lang="ts-type"}                   | Splits the text again [after you change it by hand](#manual-content-updates-require-refresh).                      |

## Avoid common mistakes

### Arrays are empty during setup

```ts
// wrong: chars.value is still [] during setup
const heading = useTemplateRef('heading')
const { chars } = useSplitText(heading, { chars: true })
useAnimate(chars.value, { opacity: [0, 1], delay: stagger(40) })

// right: pass the ref itself, and create the stagger inside a getter
useAnimate(chars, () => ({ opacity: [0, 1], delay: stagger(40) }))
```

The elements do not exist until the component mounts, so `lines`, `words`, and
`chars` are empty during setup. `chars.value` reads that empty array and the
animation gets no targets. A ref given to the animation composable is read
again after each split. Each split can produce a different number of
characters, so the stagger belongs
[inside a getter](/composables/utilities#stagger-a-list-that-can-grow).

### Render changing text with v-once

```vue
<script setup lang="ts">
const heading = useTemplateRef('heading')
const name = ref('Ada')
const html = computed(() => `Hello <strong>${name.value}</strong>`)
const { chars } = useSplitText(heading, { chars: true }, { html })
</script>

<template>
  <!-- wrong: Vue patches text that the split already replaced -->
  <h1 ref="heading">Hello <strong>{{ name }}</strong></h1>

  <!-- right: Vue renders the text once, the html option handles changes -->
  <h1 ref="heading" v-once v-html="html" />
</template>
```

Each split rebuilds the element from the text AnimeJS stored on the first
split, so text Vue renders into the element later is overwritten. `v-once`
stops Vue from touching the element after its first render, and the `html`
option passes new text to the split instead.

### Manual content updates require refresh

```ts
const heading = useTemplateRef('heading')
const { refresh } = useSplitText(heading, { chars: true })

function rename() {
  if (!heading.value) return
  heading.value.textContent = 'Updated message'
  refresh()
}
```

`nanime` attaches no DOM mutation observers to split elements, so without
`refresh()` the split stays on the old text.
