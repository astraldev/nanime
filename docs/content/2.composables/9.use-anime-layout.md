`useAnimeLayout` wraps the [createLayout](https://animejs.com/documentation/layout)
function from AnimeJS. It records the position and size of every element
inside a container. After a change, it animates each element from the
recorded state to the new one.

`nanime` creates the layout once the container mounts and reverts it on
unmount. It rebuilds the layout only when the container element changes or
the parameters change in value. Callbacks such as `onComplete` are left out
of that comparison.

## Signature

```ts
function useAnimeLayout(
  target: MaybeRef<AnimeLayoutTargets>,
  parameters?: MaybeRefOrGetter<AutoLayoutParams>
): BufferedProxyReturns<NanimeLayout>
```

## Parameters

::field-group
  :::field{required name="target" type="MaybeRef<AnimeLayoutTargets>"}
  The container whose children are animated. Accepts a CSS selector, a DOM
  element, a template ref or a component ref.
  :::

  :::field{name="parameters" type="MaybeRefOrGetter<AutoLayoutParams>"}
  Default timing for every `animate()` call, and what the layout tracks.

  | Option      | Type                                                             | Default          |
  | :---------- | :--------------------------------------------------------------- | :--------------- |
  | `duration`  | `number`{lang="ts-type"} or `FunctionValue`{lang="ts-type"}      | `350`            |
  | `delay`     | `number`{lang="ts-type"} or `FunctionValue`{lang="ts-type"}      | `0`              |
  | `ease`      | `EasingParam`{lang="ts-type"} or `FunctionValue`{lang="ts-type"} | `'inOut(3.5)'`   |
  | `children`  | `LayoutChildrenParam`{lang="ts-type"}                            | `'*'`            |
  | `enterFrom` | `LayoutStateParams`{lang="ts-type"}                              | `{ opacity: 0 }` |
  | `leaveTo`   | `LayoutStateParams`{lang="ts-type"}                              | `{ opacity: 0 }` |
  :::
::

## Returns

Returns a buffered proxy around the AnimeJS `AutoLayout`
instance, so every method and property it has (`record`, `animate`,
`update`, `revert`, and the rest) is available on it. See the
[AnimeJS layout documentation](https://animejs.com/documentation/layout)
for the full surface. `record()` is buffered before mount and replays once
the layout exists. Other members read as `undefined` until then.

The proxy adds one method, `patch(callback, params?)`. It calls `record()`,
awaits `callback`, waits for Vue's `nextTick()`, then returns
`animate(params)`. The callback can be async. An AnimeJS timeline is
thenable, so `await layout.patch(...)` resolves when the animation
finishes.

## Caveats

### Use `patch()`, not `update()`, for Vue state

```ts
// wrong: animate() runs before Vue has patched the DOM
layout.update(() => items.value.reverse())

// right: patch() waits for nextTick() before animating
await layout.patch(() => items.value.reverse())
```

AnimeJS `update()` records, runs the callback and animates in one
synchronous call. Vue applies state changes to the DOM on the next tick, so
`animate()` compares the old DOM with itself and nothing moves. `patch()`
awaits `nextTick()` between the two steps. `update()` still works for
direct DOM changes, such as `appendChild`.
