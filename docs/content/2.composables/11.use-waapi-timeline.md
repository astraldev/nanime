`useWaapiTimeline` builds a native
[Web Animations](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API){target="_blank"}
timeline. Add steps with `tween()` and place each one with `at`, as in
AnimeJS's `createTimeline()`. It builds on the first playback call and
cancels its animations when the component unmounts. Coming from
[`useAnimeTimeline`](/composables/use-anime-timeline), read
[Avoid common mistakes](#avoid-common-mistakes) first, because `'<'` and an
omitted `at` place tweens differently here.

::warning
**Experimental.** The API can change, or the entry can be removed, between
releases. It is not auto-imported, so import it from
`#nanime/experimental`.
::

## Build a timeline

:render-code-block-preview{src="examples/composables/WaapiTimelineDemo.vue"}

`point(name, at)` names a time, so later tweens and callbacks can start
there. `callback(fn, 'turned')` runs `fn` when the playhead reaches the
`turned` point. `callback()` takes the same positions as `at`.

Callbacks run when the playhead crosses their time, in both directions. With
callbacks at `200` and `600`, `play()` runs `200` then `600`, and `reverse()`
runs `600` then `200`. `seek()` jumps over callbacks without running them.

**Absolute and named**

| `at` | Starts at |
| :-- | :-- |
| omitted | `0`, the timeline start. |
| `120` | 120ms from the start. Negative numbers are allowed. |
| `'open'` | The time of a point registered earlier with `point('open', ...)`. |

::warning
A string that is not a point or a `<` shift, such as `'20%'` or `'120'`, is
read as a point name, so it throws unless a point has that name. Write a
time as a number: `120`.
::

**Relative to the previous tween**

The examples assume the previous tween starts at `400` and lasts `1000ms`.

| `at` | Starts at | How |
| :-- | :-- | :-- |
| `'<'` | `400` | The previous tween's start. |
| `'< + 150'` | `550` | 150ms after the previous start. |
| `'< - 150'` | `250` | 150ms before the previous start. |
| `'< + 20%'` | `600` | 20% of the previous duration (200ms) after its start. |
| `'< + 100%'` | `1400` | The previous tween's end. |
| `'< + 0.2s'` | `600` | `s` and `ms` work as units. |
| `'< + 20% + 150ms'` | `750` | Shifts add up. |

**Relative to a point**

The examples assume `point('open', 2000)` registered after that same tween.
A point registered before any tween has no tween to measure, so
`'open + 20%'` is the same as `'open'`.

| `at` | Starts at | How |
| :-- | :-- | :-- |
| `'open + 150'` | `2150` | 150ms after `open`. |
| `'open - 20%'` | `1800` | 200ms before `open`: 20% of the last tween registered before the point. |
| `'open 50% + 150ms'` | `2650` | The first shift can leave out its sign. |

## Control playback

:render-code-block-preview{src="examples/composables/WaapiTimelinePlaybackDemo.vue"}

While the timeline runs or is paused, `reverse()` turns it around from where
it is. Before the first play or after the end, it starts from the end. Each
tween runs from its `to` value back to its `from` value, with the
[reverse curve](#easing) if you set one. To drive a scrub bar, call
`seek(progress * timeline.duration)` on input, and read `progress` in a
`requestAnimationFrame` loop while `isRunning` is `true`.

::warning
On the returned timeline, only `isRunning` is a ref. `progress`,
`currentTime`, `paused` and `completed` are getters that
[do not update a template](/composables/composable-lifecycle#properties-do-not-update-templates),
so the demo reads them in a `watch` on `isRunning`.
::

## API

```ts
function useWaapiTimeline(options?: WaapiTimelineOptions): WaapiTimelineRef
```

::field-group
  :::field{name="options" type="WaapiTimelineOptions"}
  See [Options](#options).
  :::
::

### Options

::field-group
  :::field{name="defaults.duration" type="number"}
  Duration of every tween without its own `duration`. Defaults to `300`.
  :::

  :::field{name="defaults.ease" type="WaapiTimelineEase"}
  Easing of every tween without its own `ease`. Accepts the same values as
  [`ease`](#easing). Defaults to `'linear'`.
  :::

  :::field{name="autoplay" type="boolean"}
  Plays when the component mounts. Defaults to `false`.
  :::

  :::field{name="fill" type="'auto' | 'none' | 'forwards' | 'both'"}
  `'auto'` gives the first tween on each property of an element
  `fill: 'both'` and every
  later one `fill: 'forwards'`, so a sequence on one property holds each end
  value without the later tweens applying early. Any other value applies to
  every tween as-is. With `'both'`, a later tween's `from` applies before it
  starts, so in a sequence on one property the first tween never appears.
  With `'none'`, the element shows its own CSS outside each tween. Defaults
  to `'auto'`.
  :::

  :::field{name="isReducedMotion" type="() => boolean"}
  When it returns `true`, `play()` jumps to the last frame, `reverse()` jumps
  to the first, and callbacks run once in playback order. Defaults to the
  module's [`reducedMotion`](/guides/accessibility) setting.
  :::

  :::field{name="onRunningChange" type="(running: boolean) => void"}
  Called with `true` when playback starts, and with `false` each time it
  pauses, finishes or is cancelled. It can be called with `false` twice in a
  row, for example on a pause and then a `seek()` to the end.
  :::
::

### Tween parameters

```ts
timeline.tween(panel, {
  // wrong: opacity: [0, 1, 0] throws, a property has one start and one end
  opacity: [0, 1],
  transform: { from: 'translateY(12px)', to: 'translateY(0)' },
  duration: 400,
  ease: 'ease-out',
  at: 'open',
})
```

The target is an element, an array of elements, a CSS selector, a component
instance, or a template ref or getter that returns one. Every key other than
`at`, `duration`, `delay` and `ease` is a CSS property. Its value is a
`[from, to]` pair, a `{ from, to }` object, or a single value that animates
from the element's current value. A later tween on the same property starts
at its own `from`, so give it the previous tween's `to`, or the element
jumps. `loop`, `sync`, `set`, `remove`, `stretch` and the `onBegin`,
`onUpdate` and `onComplete` callbacks do not exist. Use `callback()` for
timed functions.

::field-group
  :::field{name="at" type="number | string"}
  When the tween starts. See [Build a timeline](#build-a-timeline) for every
  form. Defaults to `0`.
  :::

  :::field{name="duration" type="number"}
  Defaults to `defaults.duration`, or to a spring's settling duration when
  `ease` is a spring.
  :::

  :::field{name="delay" type="number"}
  Added to the start from `at`. Defaults to `0`.
  :::

  :::field{name="ease" type="WaapiTimelineEase"}
  See [Easing](#easing). Defaults to `defaults.ease`.
  :::
::

::warning
Values go to the Web Animations API as-is. CSS properties such as
`translate`, `rotate` and `scale` work, but lengths need units, and
AnimeJS-only names such as `x` and `y` do nothing, with no error. A
`stagger()` value throws. Use
[`useWaapiAnimate`](/composables/use-waapi-animate) for those.
::

### Easing

`ease` takes an AnimeJS easing (`'outBack(3)'`, a function, a spring) or a
CSS easing (`'ease-out'`, `'cubic-bezier(...)'`, `'steps(...)'`). Pass
`{ forward, reverse }` to use another curve while the timeline plays
backward:

```ts
timeline.tween(panel, {
  opacity: [0, 1],
  ease: { forward: 'outQuad', reverse: 'inQuad' },
})
```

`reverse` defaults to `forward`. A curve played backward runs from its end
to its start, so `inQuad` on the way back looks like `outQuad` on the way
forward.

::warning
An unknown easing name logs a warning once and falls back to `'linear'`.
::

### Returns

Returns a `WaapiTimelineRef`{lang="ts-type"}: a plain object whose methods do
not depend on `this`, so destructuring works. Every method returns the same
timeline, so calls chain. The Types block lists each member and what it
does.

You can call `play()` or `seek()` in `setup()`. Until the component mounts,
the call waits, so the timeline builds once template refs point at elements.
The first call to `play()`, `reverse()`, `restart()`, `alternate()` or
`seek()` builds the timeline, and after it `tween()`, `point()` and
`callback()` throw. In `setup()` that call waits for mount, so a `tween()`
registered after a queued `play()` still counts. A bad position or value,
or a callback before `0`, throws at the `tween()`, `point()` or
`callback()` call that has it.

### createWaapiTimeline

`createWaapiTimeline()` is the same timeline without mount and unmount
handling, and `isRunning` is a plain boolean. It ignores the module's
`reducedMotion` setting unless you pass `isReducedMotion`. Import it from
`#nanime/experimental`, or `nanime/experimental` in a Vue app, and call
`cancel()` when you are done:

```ts
const timeline = createWaapiTimeline()
timeline.tween('.panel', { opacity: [0, 1] })
timeline.play()
```

Its targets are DOM elements, arrays, selectors, node lists, or a function
that returns one.

::collapsible{name="Types"}
```ts
interface WaapiTimelineRef {
  // add steps; all three throw after the first playback call
  tween: (target: WaapiTimelineRefTarget, params: WaapiTweenParams) => WaapiTimelineRef
  // (fn, at) or ({ fn, at }); at defaults to 0, a callback past the last tween lengthens the timeline
  callback: (input: WaapiTimelineCallbackInput, at?: WaapiTimelinePosition) => WaapiTimelineRef
  // register a point before the tweens that use it
  point: (name: string, at: WaapiTimelinePosition) => WaapiTimelineRef

  // from a pause: continue; running the other way: turn around; finished: replay from 0
  play: () => WaapiTimelineRef
  // play() in the other direction; finished: replay from the end
  reverse: () => WaapiTimelineRef
  // does nothing unless running
  pause: () => WaapiTimelineRef
  // continue a paused timeline in its direction
  resume: () => WaapiTimelineRef
  // seek to 0 and play forward
  restart: () => WaapiTimelineRef
  // play the other way; a timeline that has not played yet plays forward
  alternate: () => WaapiTimelineRef
  // ms, clamped; keeps running unless it lands on an end; skips callbacks
  seek: (time: number) => WaapiTimelineRef
  // remove the animations so elements show their own CSS; next play rebuilds
  cancel: () => WaapiTimelineRef

  // true while playing in either direction
  readonly isRunning: Readonly<Ref<boolean>>
  // ms, known before the first build
  readonly duration: number
  // ms, 0 before the first build
  readonly currentTime: number
  // currentTime / duration, 0 to 1
  readonly progress: number
  // after pause(), or a seek() that stops before the end
  readonly paused: boolean
  // reached an end and stopped
  readonly completed: boolean
}

type WaapiTimelineElement
  = | HTMLElement
    | SVGElement
    | HTMLElement[]
    | SVGElement[]
    | ComponentPublicInstance

type WaapiTimelineRefTarget
  = | WaapiTimelineElement
    | string
    | null
    | undefined
    | MaybeRefOrGetter<WaapiTimelineElement | string | null | undefined>

interface WaapiTimelineCallback {
  fn: () => void
  at?: WaapiTimelinePosition
}

type WaapiTimelineCallbackInput = (() => void) | WaapiTimelineCallback

type WaapiTimelinePosition = number | string
type WaapiTimelineValue = string | number
type WaapiTimelinePair = readonly [string, string] | readonly [number, number]

interface WaapiTimelineRange {
  from?: WaapiTimelineValue
  to?: WaapiTimelineValue
}

type WaapiTimelineFrame = WaapiTimelineValue | WaapiTimelinePair | WaapiTimelineRange

type WaapiTimelineFill = 'auto' | 'none' | 'forwards' | 'both'

interface WaapiTimelineEasePair {
  forward: EasingParam
  reverse?: EasingParam
}

type WaapiTimelineEase = EasingParam | WaapiTimelineEasePair

interface WaapiTimelineDefaults {
  duration?: number
  ease?: WaapiTimelineEase
}

interface WaapiTimelineOptions {
  defaults?: WaapiTimelineDefaults
  autoplay?: boolean
  fill?: WaapiTimelineFill
  isReducedMotion?: () => boolean
  onRunningChange?: (running: boolean) => void
}

type WaapiTweenParams = {
  at?: WaapiTimelinePosition
  duration?: number
  delay?: number
  ease?: WaapiTimelineEase
} & Record<string, WaapiTimelineFrame | WaapiTimelinePosition | WaapiTimelineEase | undefined>
```
::

## Avoid common mistakes

### Don't use `<` for the previous end

```ts
timeline
  .tween(first, { opacity: [0, 1] })
  // wrong: at: '<' starts with first, not after it
  .tween(second, { opacity: [0, 1], at: '< + 100%' })
```

With `at: '<'`, the second tween runs together with the first and no error
is raised. In AnimeJS `<` is the previous tween's end, `<<` is its start and
an omitted position appends. Here `<` is the start, `<<` throws and an
omitted `at` is `0`. Write `'< + 100%'` for the previous end.

### Fix a tween that never runs

```ts
const panel = useTemplateRef('panel') // inside v-if="open"

timeline.tween(panel, { opacity: [0, 1] })

watch(panel, (element) => {
  // wrong: timeline.play()
  if (element) timeline.cancel().play()
})
```

The timeline looks up its targets once, at the first playback call. A target
that is `null` then is skipped with no error. Each time the `v-if` opens, it
also renders a new element that the old build never saw. Watch the template
ref, and call `cancel()` before `play()` so the timeline looks the ref up
again.
