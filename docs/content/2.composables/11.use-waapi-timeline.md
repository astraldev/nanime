::warning
**Experimental.** The API can change, or the entry can be removed, between
releases. The experimental entry is **not auto-imported**. Import it from
`#nanime/experimental` in a Nuxt app, or `nanime/experimental` in a Vue app.
The stable composables are unaffected.
::

`useWaapiTimeline` builds a native
[Web Animations](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API){target="_blank"}
timeline. Each property in a tween becomes an `Animation` with a delay and
an end delay, aligned to one clock. The browser drives playback. The API
keeps the step and position model of AnimeJS's `createTimeline()` and runs
functions at times with `callback()`.

## Import

```ts
import { createWaapiTimeline, useWaapiTimeline } from '#nanime/experimental'
```

The experimental code is in its own entry, outside the auto-import
directory. An app that never imports it does not bundle it. In a Vue app
without Nuxt, import from `nanime/experimental` instead.

## Create a timeline without a component

`createWaapiTimeline()` returns a timeline with the same methods, without
the component lifecycle. Targets are elements, arrays, CSS selectors, node
lists, or a function that returns one when the timeline builds:

```ts
const timeline = createWaapiTimeline()
timeline.tween(panel, { opacity: [0, 1] })
timeline.play()
```

It builds on the first play, so create it on the client. Call `cancel()`
when you are done. `useWaapiTimeline()` adds the mount and unmount handling.

## A timeline of positioned tweens

:render-code-block-preview{src="examples/composables/WaapiTimelineDemo.vue"}

The example registers a named time with `point('open', 0)`, then sets
`at: 'open'` on the tween. `at` is the position: a time in milliseconds or a
point name.

| `at` | Resolves to |
| :-- | :-- |
| omitted | `0`, the timeline start. |
| `120` | 120ms from the start. Negative numbers are allowed. |
| `'open'` | The time of a point registered earlier. |
| `'<'` | The previous tween's start. |
| `'<+150'` | 150ms after the previous tween starts. |
| `'<-150'` | 150ms before the previous tween starts. |
| `'<+20%'` | 20% of the previous tween's duration after it starts. |
| `'<-20%'` | 20% of the previous tween's duration before it starts. |
| `'<+100%'` | The previous tween's end. |
| `'<+0.2s'` | Seconds and milliseconds are both accepted after `<`. |
| `'open+150'` | 150ms after the `open` point. |
| `'open-20%'` | 20% of the previous tween's duration before the `open` point. |
| `'open + 1s'` | Spaces around the sign are allowed. |
| `'open 50% + 150ms'` | Half the point's duration, plus 150ms. |
| `'< + 20% + 150ms'` | 20% of the previous duration after its start, plus 150ms. |

`<` is the previous tween's start. A `+` or `-` shifts from that point, so
`'<+100%'` lands at the previous tween's end. Shifts add, so
`'< + 20% + 150ms'` starts 20% into the previous tween, plus 150ms. The
first shift can omit its sign. Absolute percentages are not supported:
`'20%'` is read as a point name.

The timeline stores the duration of the tween before each point. A
percentage shift from a point is a fraction of that duration, the same kind
of base `<±X%` uses. A point declared before any tween has a zero base, so
`'open-20%'` resolves to `open`.

## Control playback

Only `isRunning` is reactive. The demo reads `progress`, `paused` and

## Run a function at a time

```ts
timeline
  .callback(() => emit('opened'), 'open')
  .callback({ fn: () => emit('settled'), at: '<+100%' })
```

`fn` runs each time the playhead crosses `at`. `at` accepts the same
positions as `tween().at` and defaults to `0`.

- Reverse playback runs callbacks in reverse order.
- `seek()` does not run callbacks.
- Reduced motion runs every callback once, in playback order.
- A callback time counts toward `duration`, so a callback after the last
  tween keeps the clock running.
- Callbacks run from a `requestAnimationFrame` loop. In a hidden tab the
  loop pauses, so they run together on the next frame or when the clock
  ends.
- A callback at `0` runs on the first forward frame.

## API

```ts
function useWaapiTimeline(options?: WaapiTimelineOptions): WaapiTimelineRef
function createWaapiTimeline(options?: WaapiTimelineOptions): WaapiTimeline
```

::field-group
  :::field{name="options" type="WaapiTimelineOptions"}
  See [Options](#options).
  :::
::

`WaapiTimelineRef` is the Vue timeline: it has a reactive `isRunning` and
accepts refs and getters. `WaapiTimeline` is the framework-free timeline from
`createWaapiTimeline`: `isRunning` is a boolean and targets are DOM targets or
a function returning one. Both return plain objects whose methods do not
depend on `this`, so destructuring works.

| Member | Type | Notes |
| :-- | :-- | :-- |
| `tween(target, params)` | `(target, params) => WaapiTimelineRef`{lang="ts-type"} | Adds one tween. `target` accepts an element, an array, a CSS selector, a component instance, or a ref/getter. `at` inside `params` sets its position. |
| `callback(fn, at?)`, `callback({ fn, at })` | `(fn, at?) => WaapiTimelineRef`{lang="ts-type"} | Runs `fn` when the playhead crosses `at`. `at` defaults to `0`. |
| `point(name, at)` | `(name, at) => WaapiTimelineRef`{lang="ts-type"} | Names a time. Points must exist before a tween uses them. |
| `play()`, `reverse()` | `() => WaapiTimelineRef`{lang="ts-type"} | Play forward or backward. The timeline stops at either end. Calling the method again replays from the other end. |
| `pause()`, `resume()` | `() => WaapiTimelineRef`{lang="ts-type"} | Stop and continue in the current direction. |
| `restart()` | `() => WaapiTimelineRef`{lang="ts-type"} | Seek to `0` and play forward. |
| `alternate()` | `() => WaapiTimelineRef`{lang="ts-type"} | Play in the opposite direction. |
| `seek(time)` | `(time: number) => WaapiTimelineRef`{lang="ts-type"} | Moves the playhead. Values outside the timeline are clamped to its ends. |
| `cancel()` | `() => WaapiTimelineRef`{lang="ts-type"} | Stops and releases the animations. The next play rebuilds from the registered tweens. |
| `isRunning` | `Readonly<Ref<boolean>>`{lang="ts-type"} | True while playing in either direction. The factory returns a plain `boolean`. |
| `duration`, `currentTime`, `progress` | `number`{lang="ts-type"} | Read-only getters. They do not update a template on their own. |
| `paused`, `completed` | `boolean`{lang="ts-type"} | Read-only state getters. |

### Options

| Option | Type | Default | Notes |
| :-- | :-- | :-- | :-- |
| `defaults.duration` | `number` | `300` | Applies to every tween without its own `duration`. |
| `defaults.ease` | `EasingParam` | `'linear'` | An AnimeJS easing (`outQuad`, `outBack(3)`), a function, a spring, or a CSS easing. |
| `autoplay` | `boolean` | `false` | With `useWaapiTimeline`, plays on mount. The factory plays at creation. |
| `fill` | `'auto' \| 'none' \| 'forwards' \| 'both'` | `'auto'` | `'auto'` uses the coverage rule below. |
| `isReducedMotion` | `() => boolean` | The app setting | Set by `useWaapiTimeline`. `createWaapiTimeline` defaults it to `false`. |
| `onRunningChange` | `(running: boolean) => void` | none | Called when `isRunning` changes. |

### Tween parameters

`at`, `duration`, `delay` and `ease` are reserved. Every other key is a CSS
property, with a `[from, to]` pair, a `{ from, to }` object, or a single
value:

```ts
timeline.tween(panel, {
  opacity: [0, 1],
  transform: { from: 'translateY(12px)', to: 'translateY(0)' },
  duration: 400,
  ease: 'ease-out',
  at: 'open',
})
```

Each property takes one start value and one end value. A `[from, to]`
pair, a `{ from, to }` object, or a single value sets them. Arrays with more
than two values throw, because intermediate keyframes are not supported.

Property values are passed to the Web Animations API as-is. Numbers work for
unitless properties such as `opacity`. Lengths need units. AnimeJS shorthands
such as `x`, `scale` or `stagger()` are not normalized here. Use
[`useWaapiAnimate`](/composables/use-waapi-animate) for those.

`ease` accepts any AnimeJS easing: a name such as `'outQuad'`, a parameterised
name such as `'outBack(3)'`, a function, or a spring. AnimeJS forms go through
`waapi.convertEase` and become a CSS `linear(...)` curve. CSS easings such as
`'ease-out'`, `'cubic-bezier(...)'` and `'steps(...)'` pass through unchanged.
A spring also sets the tween duration to its settling duration unless you set
`duration` yourself.

## Fill and reverse playback

A browser animation with `fill: 'both'` applies its values even outside its
active time. Two tweens on the same element and property then both apply
from the first frame, and the later tween's `from` value overrides the
earlier tween's.

With `fill: 'auto'` the timeline sorts the tweens per element and property:

- the first tween uses `fill: 'both'`, so the initial `from` state applies
  and the end state holds until the next tween starts
- every later tween uses `fill: 'forwards'`, so it does not apply before it
  starts and holds its end value afterwards

Set `fill` to `'none'`, `'forwards'` or `'both'` to apply one value to every
animation instead. With `'none'`, the element falls back to its own CSS
outside each tween.

Reverse playback traverses the same values backwards. A tween written as
`[0, 1]` goes from `1` back to `0`, and its easing runs backwards too.

## Lifecycle

- Tweens, points and callbacks store data. Nothing touches the DOM until the
  first play, after mount.
- With `useWaapiTimeline()`, calls to `play()`, `reverse()` or `seek()` in
  `setup()` are queued until the component mounts, so template refs are
  populated.
- Targets resolve once, at the first play. A ref that is `null` at that
  point is skipped. Call `cancel()` and play again to resolve a changed ref.
- After the first play, `tween()` and `point()` throw, so register everything
  before playing.
- With `useWaapiTimeline()`, the animations cancel when the component
  unmounts.

## Reduced motion

When [`reducedMotion`](/guides/accessibility) is `'always'`, or `'system'`
and the visitor's `prefers-reduced-motion` setting is `reduce`, `play()` jumps
to the last frame and `reverse()` jumps to the first. Nothing animates, and
`isRunning` stays `false`.

## Limitations

- No `onBegin`/`onUpdate`/`onComplete`. Use `callback()` for time-based
  functions, and observe `isRunning` for state.
- No `loop`, `sync`, `set`, `remove` or `stretch`.
- CSS values only. No JS objects, SVG attributes outside CSS, AnimeJS
  shorthands or springs.
- No intermediate keyframes, keyframe offsets or per-keyframe easing. Each
  property has one start and one end value.
- One build per registration. `cancel()` rebuilds, but the tweens themselves
  do not change.
- When tweens overlap on the same property, the later tween overrides the
  earlier one.
- The first tween on a property applies its `from` value as soon as the
  timeline is built, even if it starts later.
