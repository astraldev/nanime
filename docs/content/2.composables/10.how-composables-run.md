The nine composables share the same rules for building, rebuilding and
tearing down their AnimeJS instance. Each
[composable page](/composables/introduction) covers its own API.

## Where you can call a composable

Call a composable in `setup()` unless you have a reason not to. The
[composables index](/composables/introduction#choosing-a-composable) marks
which composables have Instant play and which are Buffered.

### Instant play

Composables with Instant play also work outside `setup()`, for example in
a click handler. There they build the animation on the next tick and read
`parameters` once, so later `ref` changes are ignored. Outside `setup()`
there is no component to read from, so:

- `app.config.ts` defaults, [`provideAnimeDefaults()`](/guides/defaults#scope-defaults-to-part-of-the-app) and presets do not apply.
- `reducedMotion` is not honored, so the animation always plays.
- Nothing reverts the animation. Call `revert()` yourself, or each call stacks another animation on the same targets.

To keep reactivity, call the composable in `setup()` and call `play()` on
the returned object from the handler. `useAnimate` autoplays on mount, so
set `autoplay: false` when the handler starts the animation:

```ts
const animation = useAnimate('.box', { opacity: [0, 1], autoplay: false })

button.addEventListener('click', () => animation.play())
```

A top-level `await` in `<script setup>` still counts as `setup()`.

### Buffered

Buffered composables build their instance after the component mounts, so
in `setup()`:

- A call to a method in the table below is queued and replayed in order
  once the instance exists.
- Any other method is `undefined`, so calling it throws a `TypeError`.
- A property read gives `undefined`.

| Composable | Queued before mount |
| :--- | :--- |
| `useAnimeTimeline` | `add`, `set`, `remove`, `call`, `label`, `sync`, `stretch`, `refresh`, `revert` and the playback methods `play`, `pause`, `resume`, `restart`, `reset`, `reverse`, `alternate`, `seek`, `cancel`, `complete`, `init`, `resetTime` |
| `useDraggable` | `disable`, `enable`, `reset`, `revert`, `stop`, `setX`, `setY`, `scrollInView`, `animateInView` |
| `useAnimeScroll` | `link`, `refresh`, `revert` |
| `useAnimeLayout` | `record` |

### Read properties after mount

`useAnimeTimeline`, `useDraggable` and `useAnimeScroll` build their
instance on the tick after the component mounts. Read properties after
`await nextTick()` inside `onMounted`, or inside a callback such as
`onDrag`:

```ts
const draggable = useDraggable('.card')

onMounted(async () => {
  await nextTick()
  console.log(draggable.x)
})
```

`useAnimeLayout` builds during mount, so its members are ready inside
`onMounted`.

### Composables that are not Buffered

`useAnimate`, `useWaapiAnimate` and `useScrambleText` return an empty
placeholder until the component mounts, so a method called during
`setup()` does nothing. `useAnimatable` has no setters until then, so
calling one throws.

## Know when an animation rebuilds

A rebuild reverts the old instance first and then builds a new one. It
restarts the animation unless
[`keepTime`](/guides/configuration#set-module-options) is on.

| Composable | Rebuilds when | Supports `keepTime` |
| :--- | :--- | :--- |
| `useAnimate` | `target` or a parameter changes | Yes |
| `useWaapiAnimate` | `target` or a parameter changes | No |
| `useAnimatable` | `target` changes. Its options are read once. | No |
| `useSplitText` | `target`, a parameter or `html` changes | No |
| `useScrambleText` | `target` or either options object changes | Yes |
| `useAnimeTimeline` | a parameter changes | Yes |
| `useDraggable` | `target`, `trigger` or `container` changes. A `ref` in the listed options updates it in place. | No |
| `useAnimeScroll` | `target` or `container` changes, or a field of its `reactive()` object changes. It takes a plain or `reactive()` object, not a `ref` or getter. | No |
| `useAnimeLayout` | the container or a parameter changes | No |

### Read changing values inside callbacks

```ts
// wrong: the callback keeps the first value of count
useAnimate(box, () => {
  const current = count.value
  return { x: 100, onComplete: () => log(current) }
})

// right: the callback reads count when it runs
useAnimate(box, { x: 100, onComplete: () => log(count.value) })
```

Most composables do not rebuild when only a callback changes, so the
running animation keeps the callback it was built with. Read the `ref`
inside the callback instead.

Three composables do rebuild when a callback changes:

- `useSplitText` rebuilds on any callback change, so a getter that returns
  a new inline function rebuilds it each time it runs.
- `useWaapiAnimate` ignores a changed `onComplete`, but rebuilds when any
  other function in the parameters is a new function.
- `useScrambleText` rebuilds on callbacks in `scrambleOptions`, not in
  `animationOptions`.

## Know which defaults and reduced motion apply

Defaults for a composable come from `nanime.composables` in `app.config.ts`,
the nearest
[`provideAnimeDefaults()`](/guides/defaults#scope-defaults-to-part-of-the-app)
call, or the active [preset](/guides/presets).

| Setting | Read by |
| :--- | :--- |
| `nanime.composables.animate` and the preset's `animate` entry | `useAnimate` |
| `nanime.composables.draggable` and the preset's `draggable` entry | `useDraggable` |
| `keepTime` | `useAnimate`, `useScrambleText`, `useAnimeTimeline` |
| `reducedMotion` | `useAnimate`, `useWaapiAnimate`, `useAnimatable`, `useScrambleText`, `useAnimeTimeline`, `useAnimeLayout` |

[Accessibility](/guides/accessibility) covers the reduced motion setting.
Under `reducedMotion`, `useAnimatable` sets every numeric option to `0` and
the easing to `linear`, `useScrambleText` completes at once, and
`useAnimeLayout` only measures the initial layout and does not animate. The
other composables jump to their end state.

A key passed as `undefined` replaces the default, so leave the key out
instead.

## Avoid common mistakes

### Do not destructure the returned instance

Applies to `useAnimate`, `useWaapiAnimate`, `useAnimatable` and
`useScrambleText`.

```ts
// wrong: play() throws when called
const { play } = useAnimate('.target', { opacity: 0 })

// right
const animation = useAnimate('.target', { opacity: 0 })
animation.play()
```

Destructured properties and setters break too:

- A property such as `progress` is copied once and never updates.
- A `useAnimatable` setter such as `x` keeps working, but after `target`
  changes it still animates the old target.

### Properties do not update templates

Applies to every composable that returns an AnimeJS instance. `useSplitText`
returns real refs and `useAnimatable` returns setters, so it does not apply
to them.

```ts
// wrong: progress never updates inside a template interpolation
// <p>{{ animation.progress }}</p>

// right: update a ref inside onUpdate
const progress = ref(0)
const animation = useAnimate('.target', {
  opacity: [0, 1],
  onUpdate: self => progress.value = self.progress,
})
```

AnimeJS updates properties like `progress` outside Vue's reactivity
tracking, so a template never re-renders for them. `useWaapiAnimate` has
no `onUpdate`, so use [`useAnimate`](/composables/use-animate) when a
template needs live progress.

### Plain object targets must be reactive

Applies to `useAnimate` and `useAnimatable`.

```ts
// AnimeJS writes to a plain object directly, so Vue never sees the change
const position = { x: 0, y: 0 }
useAnimate(position, { x: 100 })

// reactive(), shallowReactive() and ref() make the object reactive
const tracked = reactive({ x: 0, y: 0 })
useAnimate(tracked, { x: 100 })
```

A `shallowRef` holding an object is not reactive.
