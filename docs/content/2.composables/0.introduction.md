## Client-side lifecycle and reactivity

Every Nanime composable runs client-only: animations require the DOM and render
nothing during server-side rendering (SSR).

When used inside `setup()`, every composable watches its inputs and automatically
rebuilds when a reactive argument (a `ref`, getter, or reactive object) changes.
The only exception is [`useAnimatable`](/composables/use-animatable), which
rebuilds only when its `target` changes; mutations to its `options` do not
rebuild the animatable controller.

## Instant play

Composables marked with the
:badge{icon="mage:zap-fill" label="Instant play" size="md" variant="soft"}
work outside `setup()`. You can call them after mount from an event handler or a
utility function. Their mode depends on whether
[`getCurrentInstance()`](https://vuejs.org/api/composition-api-helpers.html#getcurrentinstance)
returns an active instance when they run:

- **Reactive mode** runs when an instance exists. Nanime watches targets and
  parameters. Changing a `ref`{lang="ts-type"} or a getter rebuilds the
  animation. With the default `keepTime: true`, the playhead carries across the
  rebuild instead of restarting. Setting `keepTime: false` reverts the
  animation on each change.
- **Instant mode** runs when no instance is present. Nanime creates the
  animation once. It reads `parameters` a single time, even if you pass a
  `ref`{lang="ts-type"}.

A top-level `await` in `<script setup>` stays in reactive mode. The Vue compiler
wraps the call in
[`withAsyncContext()`](https://vuejs.org/api/sfc-script-setup.html#top-level-await),
which restores the instance after the promise settles. Other asynchronous
contexts run without an instance. These include event handlers, watchers,
`setTimeout` callbacks, nested async functions, and Options API `async setup()`
hooks.

```ts
// instant: this runs after setup(), so there is no instance to find
button.addEventListener('click', () => {
  const anim = useAnimate('.box', () => ({ opacity: opacityRef.value }))
  // opacityRef changes are ignored from here on
})
```

::tip
Nanime does not warn you when this happens, and the animation still runs.
Only reactivity is lost. To keep reactivity and trigger playback later, call
the composable in `setup()` and control it through the returned instance.
::

`useDraggable`, `useSplitText`, and `useAnimeScroll` do not use this mechanism.
They have no instant mode and must be called from `setup()`, because they depend
on the component's mount lifecycle.
