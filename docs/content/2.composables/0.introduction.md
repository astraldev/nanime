## When does an animation rebuild?

Composables run on the client only. Called in `setup()`, a composable
rebuilds its animation when a `ref`, getter or reactive object it receives
changes. The rebuild restarts the animation, unless
[`keepTime: true`](/guides/configuration#set-module-options)
carries the playhead over. Each page lists what else triggers a rebuild,
such as a new `target`.

[`useAnimate`](/composables/use-animate) and
[`useDraggable`](/composables/use-draggable) also read
[defaults](/guides/configuration#set-app-wide-defaults) from
`app.config.ts` or `provideAnimeDefaults()`.

## Instant play

Composables marked
:badge{icon="mage:zap-fill" label="Instant play" size="md" variant="soft"}
also work outside `setup()`, for example in a click handler. There they
build the animation once and read `parameters` a single time, so later
`ref` changes are ignored. No warning is logged.

```ts
button.addEventListener('click', () => {
  // opacityRef changes after this call are ignored
  useAnimate('.box', () => ({ opacity: opacityRef.value }))
})
```

To keep reactivity, call the composable in `setup()` and call `play()` on
the returned instance from the handler. A top-level `await` in
`<script setup>` still counts as `setup()`.

## Buffered

Composables marked
:badge{icon="ph:stack" label="Buffered" size="md" variant="soft"}
create their instance after mount. Methods that return the instance, like
`play()`, can be called before then. `nanime` queues them and replays them
in order once the instance exists. Other properties and methods read
`undefined` until then, as
[read properties after mount](#read-properties-after-mount) shows.
`useAnimeTimeline` called outside `setup()` creates its instance at once.

## Caveats that apply across composables

### Do not destructure the returned instance

Applies to `useAnimate`, `useWaapiAnimate`, `useAnimatable` and
`useScrambleText`.

```ts
// wrong: play() throws when called
const { play } = useAnimate('.target', { opacity: 0 })

// right
const animation = useAnimate('.target', { opacity: 0 })
animation.play()
```

The proxy hands back methods without their instance, so a destructured
`play()` runs with no `this` and throws. A destructured property such as
`progress` is a copy of the value at that moment. A destructured
`useAnimatable` setter such as `x` carries its own instance and works
until `target` changes, then keeps driving the old animatable. Keep the
returned object and call methods on it.

### Properties do not update templates

Applies to `useAnimate`, `useWaapiAnimate`, `useScrambleText` and
`useAnimeScroll`.

```ts
// wrong: progress never updates inside a template interpolation
// <p>{{ animation.progress }}</p>

// right: update a ref inside onUpdate
const progress = ref(0)
const animation = useAnimate('.target', {
  opacity: [0, 1],
  onUpdate: self => progress.value = self.progress,
})
```

Interpolating properties like `progress` in a template displays only their
initial value. AnimeJS updates them outside Vue's reactivity tracking, so
nothing triggers a re-render. Assign the current value to a `ref` inside
the `onUpdate` callback. `useWaapiAnimate` has no `onUpdate`, so use
[`useAnimate`](/composables/use-animate) when a template needs live
progress.

### Read properties after mount

Applies to the buffered composables.

```ts
// wrong: the instance does not exist yet
const draggable = useDraggable('.card')
console.log(draggable.x) // undefined

// right
onMounted(() => {
  console.log(draggable.x)
})
```

The instance is created after the component mounts, so property reads and
non-chainable methods return `undefined` until then. Chainable methods such
as `add()`, `play()` and `link()` are queued and replayed in order. Read
properties after mount or inside a callback such as `onDrag`.

### Plain object targets must be reactive

Applies to `useAnimate` and `useAnimatable`.

```ts
// wrong: AnimeJS writes to the object's properties directly, bypassing .value
const position = ref({ x: 0, y: 0 })
useAnimate(position, { x: 100 })

// right
const position = reactive({ x: 0, y: 0 })
useAnimate(position, { x: 100 })
```

AnimeJS writes to properties on the target without touching `.value`, so
mutations to a `ref` holding an object bypass Vue and the template never
updates. Wrap plain objects in `reactive` or `shallowReactive` so property
updates trigger re-renders.
