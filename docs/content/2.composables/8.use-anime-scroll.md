`useAnimeScroll` wraps the [onScroll](https://animejs.com/documentation/scroll){target="_blank"}
function from AnimeJS. It tracks an element relative to its scroll container and
links animation progress directly to the scrollbar position.

Nanime rebuilds the scroll observer when parameters change and automatically
cleans up scroll listeners when the component unmounts.

## Usage

:render-code-block-preview{src="examples/composables/AnimeScrollDemo.vue"}

## Signature

```ts
function useAnimeScroll(
  parameters?: MaybeRefOrGetter<ScrollObserverParams>
): BufferedProxyReturns<ScrollObserver>
```

## Parameters

::field-group
  :::field{name="parameters" type="MaybeRefOrGetter<ScrollObserverParams>"}
  Where to watch, and how scroll position maps onto the animation.

  | Option | Type | Default |
  | :--- | :--- | :--- |
  | `target` | `TargetsParam`{lang="ts-type"} | The linked animation's target, else `document.body` |
  | `container` | `TargetsParam`{lang="ts-type"} | `document.body` |
  | `enter` | `ScrollThresholdParam`{lang="ts-type"} | `'end start'` |
  | `leave` | `ScrollThresholdParam`{lang="ts-type"} | `'start end'` |
  | `sync` | `boolean \| number \| string \| EasingParam`{lang="ts-type"} | `'play pause'` |
  :::
::

## Returns

Returns a buffered proxy around the AnimeJS `ScrollObserver`{lang="ts-type"}
instance.

| Member | Type | Notes |
| :--- | :--- | :--- |
| `link(animation)` | `(animation: Tickable \| WAAPIAnimation) => this`{lang="ts-type"} | Links an animation to scrub with scroll position. Buffered before mount. |
| `refresh()` | `() => this`{lang="ts-type"} | Recalculates scroll boundaries and element geometry. Buffered before mount. |
| `revert()` | `() => this`{lang="ts-type"} | Removes scroll event listeners and resets state. Buffered before mount. |
| `progress` | `number`{lang="ts-type"} | Current scroll progress between `0` and `1`. Does not update templates; see the [template reactivity caveat](#progress-does-not-update-in-a-template). |
| `velocity` | `number`{lang="ts-type"} | Instantaneous scrolling velocity. |

::warning
Reading observer properties like `progress` does not trigger template
re-renders. See the [template reactivity caveat](#progress-does-not-update-in-a-template).
::

## Caveats

### Wrap element parameters in a getter function

```ts
// wrong: reads template ref during setup before mount
const section = useTemplateRef('section')
const scroll = useAnimeScroll({ target: section.value })

// right: wrap parameters in a function to evaluate after mount
const scroll = useAnimeScroll(() => ({ target: section.value }))
```

Template refs evaluate to `null` during setup before the DOM renders. Passing a
plain object reads `section.value` immediately as `null`, causing AnimeJS to
fall back to watching the viewport instead of the intended container. Wrap the
parameters object in a getter function so targets resolve after mount.

### Give each animation its own observer

```ts
// wrong: second animation replaces the first on the observer
useAnimate(car, { autoplay: scroll })
useAnimate(trail, { autoplay: scroll })

// right: create a separate observer for each animation
const carScroll = useAnimeScroll(params)
const trailScroll = useAnimeScroll(params)
useAnimate(car, { autoplay: carScroll })
useAnimate(trail, { autoplay: trailScroll })
```

An AnimeJS scroll observer manages only one linked animation at a time. Passing
the same observer instance to multiple animations causes the second animation
to overwrite the first, leaving previous animations frozen in place. Instantiate
a separate observer for each animation.

### Progress does not update in a template

```ts
// wrong: progress never updates inside a template interpolation
// <p>{{ scroll.progress }}</p>

// right: track progress via a ref updated in onUpdate
const progress = ref(0)
const scroll = useAnimeScroll(() => ({
  onUpdate: observer => progress.value = observer.progress,
}))
```

Interpolating `{{ scroll.progress }}` displays the initial value and never
updates. The returned proxy tracks the observer instance rather than internal
numeric state, so scrolling triggers no component re-renders. Update a
`ref`{lang="ts-type"} inside the `onUpdate` callback to display live scroll
progress.
