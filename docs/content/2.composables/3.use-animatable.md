`useAnimatable` wraps [`createAnimatable()`](https://animejs.com/documentation/animatable)
from AnimeJS. It rebuilds the animatable when `target` points to a different
element, and reverts it when the component unmounts.

## API

```ts
function useAnimatable(
  target: AnimeTargets,
  options?: MaybeRefOrGetter<AnimatableParams>
): AnimatableObject
```

::field-group
  :::field{name="target" type="AnimeTargets" required}
  Accepts everything AnimeJS accepts, plus template refs and component
  refs. A plain object [must be reactive](/composables/how-composables-run#plain-object-targets-must-be-reactive).
  :::

  :::field{name="options" type="MaybeRefOrGetter<AnimatableParams>"}
  Accepts a plain object, a `ref` or a getter. A property listed here gets a
  setter, and its number is the duration of that setter's tweens. The options
  are read once, when the animatable is built, so
  [changing them alone does not rebuild it](#changing-options-alone-does-not-rebuild-the-animatable).
  :::
::

Returns the AnimeJS `AnimatableObject`{lang="ts-type"}. The setters exist
only after the component mounts, so
[a setter called during](#call-setters-after-the-component-mounts) [`setup()`](#call-setters-after-the-component-mounts) [throws](#call-setters-after-the-component-mounts).
Call setters on the returned object, as in `animator.x(100)`, because
[a destructured setter throws](/composables/how-composables-run#do-not-destructure-the-returned-instance).

## Avoid common mistakes

### Call setters after the component mounts

```ts
// wrong: x does not exist until mount
const animator = useAnimatable(box, { x: 400 })
animator.x(100)

// right: an event handler runs after mount
function follow(event: PointerEvent) {
  animator.x?.(event.offsetX)
}
```

`useAnimatable` creates the animatable when the component mounts, because
AnimeJS needs the element. Until then `animator.x` is `undefined`, so calling
it throws `animator.x is not a function`.

### Changing options alone does not rebuild the animatable

```ts
// wrong: the duration is read once, so changing durationRef does nothing
const durationRef = ref(300)
const animator = useAnimatable(box, () => ({ x: durationRef.value }))

// right: pass the duration to the setter
animator.x?.(200, durationRef.value)
```

The animatable rebuilds only when `target` points to a different element, so
a ref inside `options` neither rebuilds nor updates it. A setter takes a
duration and an easing as its second and third arguments.
