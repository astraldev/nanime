`useWaapiAnimate` wraps the [waapi.animate](https://animejs.com/documentation/web-animation-api){target="_blank"}
function from AnimeJS. It drives animations through the browser's native Web
Animations API instead of a JavaScript loop.

For properties like `transform` and `opacity`, the browser runs keyframes on the
compositor thread. This maintains steady frame rates even when the main thread
handles heavy computation.

## Usage

:render-code-block-preview{src="examples/composables/WaapiAnimateDemo.vue"}

## Signature

```ts
function useWaapiAnimate(
  target: WaapiTargets,
  parameters?: MaybeRefOrGetter<WAAPIAnimationParams>
): WAAPIAnimation
```

## Parameters

::field-group
  :::field{name="target" type="WaapiTargets" required}
  The DOM element or elements to animate. Accepts CSS selectors, DOM elements,
  and component or template refs.
  :::

  :::field{name="parameters" type="MaybeRefOrGetter<WAAPIAnimationParams>"}
  Animation settings and keyframe descriptions.

  | Option | Type | Default |
  | :--- | :--- | :--- |
  | `duration` | `number \| WAAPIFunctionValue`{lang="ts-type"} | `1000` |
  | `delay` | `number \| WAAPIFunctionValue`{lang="ts-type"} | `0` |
  | `ease` | `WAAPIEasingParam`{lang="ts-type"} | `'out(2)'` |
  | `loop` | `number \| boolean`{lang="ts-type"} | `0` |
  :::
::

## Returns

Returns a reactive proxy around the AnimeJS `WAAPIAnimation`{lang="ts-type"}
instance, so every method and property it has (`play`, `pause`, `restart`,
`revert`, `progress`, and the rest) is available on it. See the
[AnimeJS WAAPI documentation](https://animejs.com/documentation/web-animation-api){target="_blank"}
for the full surface. Two things work differently through this proxy:

- Methods are destructuring-unsafe. See the
  [destructuring caveat](#do-not-destructure-the-returned-instance).
- `progress` does not trigger Vue template re-renders. See the
  [template reactivity caveat](#progress-and-playback-properties-do-not-update-templates).

## Caveats

### Plain JavaScript objects are not valid targets

```ts
// wrong: WAAPI cannot animate plain objects
const state = reactive({ count: 0 })
useWaapiAnimate(state, { count: 100 })

// right: use useAnimate for JavaScript objects
useAnimate(state, { count: 100 })
```

The Web Animations API operates exclusively on DOM elements and SVG elements.
Passing plain JavaScript objects or primitive refs causes AnimeJS to fail
silently without rendering motion. Reach for `useAnimate`{lang="ts-type"}
whenever animating plain objects, data values, or canvas properties.

### Do not destructure the returned instance

```ts
// wrong: copies methods once, losing the link on rebuild
const { play } = useWaapiAnimate('.target', parameters)

// right: calls play on the active proxy
const animation = useWaapiAnimate('.target', parameters)
animation.play()
```

Destructuring properties or methods off the returned proxy binds them to the
initial instance. When reactive parameters change and rebuild the animation,
destructured functions continue targeting the discarded instance. Retain the
proxy object and invoke methods directly on it.

### Progress and playback properties do not update templates

```ts
// wrong: progress never updates inside a template interpolation
// <p>{{ animation.progress }}</p>
```

Interpolating properties like `progress` in a template displays only their
initial value. `WAAPIAnimation`{lang="ts-type"} has no per-frame callback.
`progress` is a getter that reads the underlying native
`Animation`{lang="ts-type"}'s `currentTime`, and reading it does not notify
Vue. [`useAnimate`](/composables/use-animate) runs its own render loop and
exposes an `onUpdate` callback instead, so reach for it when a template needs
to track progress live.
